17 Projekt 5

KI-E-Mail-Assistent

In diesem Projekt liest n8n neue E-Mails, lässt einen AI Agent die Nachricht klassifizieren, erzeugt einen Antwortentwurf und meldet dringende Fälle an dein Team. Wichtig: Der Workflow sendet keine Antwort automatisch. KI schlägt vor, der Mensch entscheidet.

⏱ ca. 50 Minuten 🎯 Niveau: Mittel bis fortgeschritten 🧩 Voraussetzung: Kapitel 6–12, 14

📋 Was du brauchst

  • Ein Test-Postfach, idealerweise Gmail. IMAP funktioniert ähnlich, aber die Node-Namen unterscheiden sich.
  • Eine Gmail-Credential mit Zugriff auf Lesen, Labels und Entwürfe.
  • Eine OpenAI- oder andere Chat-Model-Credential für den AI Agent.
  • Eine Slack-Credential oder einen anderen Benachrichtigungskanal für dringende Fälle.
  • Test-E-Mails. Keine produktiven Kundenmails, bevor du die Klassifikation geprüft hast.
KI ist kein Autopilot Dieses Kapitel baut bewusst einen Assistenten, keinen automatischen Absender. Eine falsche Antwort kann rechtlich, fachlich oder menschlich teuer werden. Der sichere Standard ist: Entwurf erstellen, markieren, Mensch prüft.

Das Ziel

Der Workflow reagiert auf neue ungelesene E-Mails. Er holt den vollständigen Inhalt, kürzt ihn auf das Nötige, fragt einen AI Agent nach Kategorie, Dringlichkeit und Antwortentwurf, verarbeitet die strukturierte Ausgabe und legt einen Gmail-Entwurf an. Sehr dringende E-Mails werden zusätzlich in Slack gemeldet.

⚡ Das robuste KI-Muster Nutze KI für Bewertung und Textentwurf, aber lasse n8n die Regeln ausführen: JSON prüfen, IF-Node verzweigen, Entwurf statt Sendung, Label statt endgültiger Entscheidung.

Schritt 1 — Testpostfach vorbereiten

Der wichtigste Schutz ist ein klar begrenzter Eingang. Wir lassen den Trigger nicht auf dein ganzes Postfach los, sondern nur auf Testmails oder ein eigenes Label.

  1. Gmail-Label anlegen

    Lege in Gmail ein Label n8n-test-ai an.

  2. Test-E-Mail senden

    Sende dir selbst eine E-Mail mit Betreff Bitte Angebot für Workshop und einem kurzen Text.

  3. Label setzen

    Markiere die Test-E-Mail mit n8n-test-ai und lasse sie ungelesen.

Warum ein Label? Trigger auf „alle ungelesenen E-Mails“ sind beim Lernen unnötig riskant. Ein Testlabel ist ein kleiner Zaun: Du entscheidest, welche Mails der Workflow überhaupt sehen darf.

Schritt 2 — Workflow und Gmail Trigger anlegen

  1. Neuen Workflow erstellen

    Erstelle einen Workflow und nenne ihn KI-E-Mail-Assistent.

  2. Gmail Trigger hinzufügen

    Klicke auf das große +, suche gmail trigger und wähle Gmail Trigger.

  3. Credential auswählen

    Wähle deine Gmail-Credential oder lege sie wie in Kapitel 12 an.

  4. Ereignis setzen

    Setze Event auf Message Received.

  5. Poll-Zeit setzen

    Setze Poll Times für den Test z. B. auf alle fünf Minuten. Später kannst du langsamer pollen.

  6. Filter setzen

    Setze Read Status auf Unread only und Label Names or IDs auf n8n-test-ai.

Wenn der Trigger nichts findet Prüfe drei Dinge: Die Mail ist ungelesen, sie hat wirklich das Label n8n-test-ai, und der Trigger nutzt dieselbe Gmail-Credential wie dein Postfach.

Schritt 3 — Vollständige E-Mail holen

Der Trigger liefert je nach Einstellung oft nur eine vereinfachte Nachricht. Für die KI brauchen wir Betreff, Absender und Textkörper. Deshalb hängen wir einen Gmail-Node an, der die Nachricht per ID holt.

  1. Gmail-Node anhängen

    Ziehe vom Gmail Trigger eine Linie ins Leere, suche gmail und wähle Gmail.

  2. Operation wählen

    Wähle Message → Get.

  3. Message ID einsetzen

    Setze das ID-Feld auf Expression und verwende {{ $json.id }}.

  4. Simplify prüfen

    Schalte Simplify ein, wenn du die Felder direkt als subject, from und text bekommst. Wenn dein Output anders aussieht, nutze die Feldnamen aus der Schema-Ansicht.

  5. Schritt ausführen

    Führe den Node aus und prüfe rechts, ob Betreff, Absender und Inhalt sichtbar sind.

Schritt 4 — E-Mail-Text vorbereiten

KI-Modelle brauchen nicht jede Signatur, jedes Tracking-Bild und jede alte Antwortkette. Wir bauen ein kompaktes Objekt, das der AI Agent lesen soll.

  1. Code-Node anhängen

    Ziehe von E-Mail holen eine Linie ins Leere, suche code und wähle Code.

  2. Node benennen

    Nenne ihn E-Mail vorbereiten.

  3. Modus wählen

    Setze den Modus auf Run Once for Each Item.

  4. Code einfügen

    Füge diesen Code ein. Falls dein Gmail-Output andere Feldnamen nutzt, passe die ersten Zeilen an.

  Code · Run Once for Each Item
const subject = $json.subject ?? $json.headers?.subject ?? '';
const from = $json.from ?? $json.headers?.from ?? '';
const rawText = $json.text ?? $json.textPlain ?? $json.snippet ?? '';

const cleaned = rawText
  .replace(/On .* wrote:/s, '')
  .replace(/--\s*[\s\S]*$/m, '')
  .replace(/\s+/g, ' ')
  .trim()
  .slice(0, 4000);

return {
  json: {
    message_id: $json.id,
    thread_id: $json.threadId,
    subject,
    from,
    email_text: cleaned
  }
};
⚡ Kontext begrenzen Mehr Text ist nicht automatisch besser. Für Klassifikation und Antwortentwurf reicht oft die aktuelle Nachricht. Alte Zitate und Signaturen erhöhen Kosten und Fehlerwahrscheinlichkeit.

Schritt 5 — AI Agent hinzufügen

Jetzt kommt der Agent. Er soll keine Tools aufrufen und keine E-Mail senden. Seine Aufgabe ist enger: klassifizieren, begründen, Entwurf formulieren.

  1. AI Agent anhängen

    Ziehe von E-Mail vorbereiten eine Linie ins Leere, suche ai agent und wähle AI Agent.

  2. Agent-Typ schlicht halten

    Nutze den Standard-Agenten bzw. eine einfache Konfiguration ohne externe Tools.

  3. Chat Model verbinden

    Klicke am AI-Agent-Node auf den Anschluss für Chat Model und wähle z. B. OpenAI Chat Model. Wähle deine Credential und ein günstiges, zuverlässiges Modell.

  4. Prompt-Modus setzen

    Setze Prompt auf Define below.

  5. User Message einfügen

    Trage den folgenden Prompt ein.

  Prompt für den AI Agent
Du bist ein vorsichtiger E-Mail-Assistent.
Analysiere die E-Mail und antworte ausschließlich als gültiges JSON.

Erlaubte Kategorien: sales, support, billing, personal, other.
Erlaubte Dringlichkeit: low, normal, high.

JSON-Schema:
{
  "category": "sales|support|billing|personal|other",
  "urgency": "low|normal|high",
  "summary": "maximal 2 Sätze",
  "reason": "kurze Begründung",
  "draft_subject": "Antwortbetreff",
  "draft_body": "höflicher Antwortentwurf in Du-Form oder neutraler Form"
}

Regeln:
- Keine Fakten erfinden.
- Wenn Informationen fehlen, im Entwurf gezielt nachfragen.
- Bei rechtlichen, medizinischen oder finanziellen Aussagen keine definitive Beratung geben.
- Niemals behaupten, dass eine Aktion bereits erledigt wurde.

E-Mail:
Von: {{ $json.from }}
Betreff: {{ $json.subject }}
Text: {{ $json.email_text }}
Wenn der Agent kein JSON liefert Prüfe, ob dein Prompt wirklich „ausschließlich gültiges JSON“ verlangt. Falls deine n8n-Version einen Output Parser oder „Require Specific Output Format“ anbietet, nutze ihn. Trotzdem solltest du den nächsten Prüfschritt behalten.

Schritt 6 — KI-Ausgabe prüfen und zerlegen

Wir vertrauen der KI-Ausgabe nicht blind. Ein Code-Node versucht, JSON zu parsen, setzt Fallbacks und markiert fehlerhafte Antworten.

  1. Code-Node anhängen

    Hänge hinter den AI Agent einen Code-Node und nenne ihn KI-Ausgabe prüfen.

  2. Modus wählen

    Setze Run Once for Each Item.

  3. Code einfügen

    Füge diesen robusten Parser ein. Je nach n8n-Version heißt das Agent-Ausgabefeld output, text oder ähnlich; passe die erste Zeile bei Bedarf an.

  Code · KI-Ausgabe prüfen
const raw = $json.output ?? $json.text ?? $json.response ?? '';
let parsed;

try {
  parsed = JSON.parse(raw);
} catch (error) {
  parsed = {
    category: 'other',
    urgency: 'normal',
    summary: 'KI-Ausgabe konnte nicht als JSON gelesen werden.',
    reason: raw.slice(0, 500),
    draft_subject: 'Re: ' + ($json.subject ?? ''),
    draft_body: 'Danke für deine Nachricht. Ich prüfe das und melde mich.',
    parse_error: true
  };
}

const allowedCategories = ['sales', 'support', 'billing', 'personal', 'other'];
const allowedUrgency = ['low', 'normal', 'high'];

return {
  json: {
    ...$json,
    category: allowedCategories.includes(parsed.category) ? parsed.category : 'other',
    urgency: allowedUrgency.includes(parsed.urgency) ? parsed.urgency : 'normal',
    summary: parsed.summary ?? '',
    reason: parsed.reason ?? '',
    draft_subject: parsed.draft_subject ?? ('Re: ' + ($json.subject ?? '')),
    draft_body: parsed.draft_body ?? 'Danke für deine Nachricht.',
    parse_error: Boolean(parsed.parse_error)
  }
};
⚡ KI-Ausgaben sind Eingaben Behandle Agent-Antworten wie Daten von außen: parsen, validieren, Defaults setzen. Erst danach darf der Workflow Entscheidungen treffen.

Schritt 7 — Entwurf in Gmail erstellen

Jetzt macht der Workflow etwas Nützliches, aber Reversibles: Er legt einen Entwurf an.

  1. Gmail-Node anhängen

    Hänge hinter KI-Ausgabe prüfen einen Gmail-Node.

  2. Operation wählen

    Wähle Draft → Create. Falls deine n8n-Version anders formuliert: Es geht um Entwurf erstellen, nicht um Senden.

  3. Empfänger setzen

    Setze To auf {{ $json.from }}. Prüfe bei echten Mails später, ob das Feld nur die Adresse enthält oder auch den Anzeigenamen.

  4. Betreff setzen

    Setze Subject auf {{ $json.draft_subject }}.

  5. Text setzen

    Setze Message auf {{ $json.draft_body }}.

  6. Schritt ausführen

    Führe den Node aus und öffne danach Gmail. Im Entwurfsordner sollte ein neuer Antwortentwurf liegen.

Nicht „Send“ wählen In manchen Gmail-Nodes liegen „Create Draft“, „Reply“ und „Send“ nah beieinander. Für dieses Kapitel ist nur Create Draft gemeint.

Schritt 8 — Dringende Fälle melden

Jetzt verzweigen wir. Nur E-Mails mit urgency = high gehen zusätzlich in Slack. Normale E-Mails bekommen nur den Gmail-Entwurf.

  1. IF-Node anhängen

    Hänge hinter KI-Ausgabe prüfen zusätzlich einen IF-Node oder setze ihn vor den Gmail-Entwurf, wenn du die Verzweigung sichtbarer haben willst.

  2. Bedingung setzen

    Prüfe {{ $json.urgency }} equals high.

  3. Slack an true-Ausgang hängen

    Hänge an den true-Ausgang einen Slack-Node mit Kanal #inbox-urgent-test.

  4. Slack-Text setzen

    Setze den Text auf die folgende Expression.

  Slack-Text
Dringende E-Mail erkannt
Von: {{ $json.from }}
Betreff: {{ $json.subject }}
Kategorie: {{ $json.category }}
Grund: {{ $json.reason }}

Zusammenfassung:
{{ $json.summary }}

Schritt 9 — Label setzen und Mail markieren

Zum Abschluss soll sichtbar sein, dass n8n diese E-Mail bearbeitet hat. Wir setzen ein Label und markieren die Nachricht erst danach als gelesen.

  1. Label vorbereiten

    Lege in Gmail ein Label n8n-ai-draft an.

  2. Gmail-Node anhängen

    Hänge nach dem Entwurf einen weiteren Gmail-Node an.

  3. Label hinzufügen

    Wähle Message → Add Label, setze die Message ID auf {{ $json.message_id }} und das Label auf n8n-ai-draft.

  4. Optional als gelesen markieren

    Füge danach einen Gmail-Node Message → Mark as Read hinzu. Mache das erst, wenn Entwurf und Label zuverlässig funktionieren.

Warum erst am Ende als gelesen? Wenn der Workflow vorher scheitert, bleibt die Mail ungelesen und taucht weiter als offene Aufgabe auf. Das ist absichtlich konservativ.

Schritt 10 — Gesamttest

  1. Normale Testmail senden

    Sende eine harmlose Anfrage mit dem Testlabel. Erwartung: Entwurf entsteht, keine Slack-Meldung.

  2. Dringende Testmail senden

    Sende eine Mail mit klarer Dringlichkeit, z. B. „Zugang funktioniert nicht, Kundentermin in 30 Minuten“. Erwartung: Entwurf und Slack-Meldung.

  3. Unklare Testmail senden

    Sende eine kurze, mehrdeutige Mail. Erwartung: Der Entwurf fragt nach, statt Details zu erfinden.

  4. Executions prüfen

    Öffne jede Ausführung. Prüfe besonders die Felder category, urgency, summary und draft_body.

  5. Workflow aktivieren

    Erst wenn alle drei Fälle passen, speichere und aktiviere den Workflow. Lasse das Testlabel zunächst bestehen.

⚡ Teste Grenzfälle, nicht nur Wunschfälle Eine KI-Demo funktioniert fast immer mit perfekten Beispielen. Relevant sind die schlechten Fälle: zu wenig Kontext, widersprüchlicher Text, Dringlichkeit ohne klare Zuständigkeit.

✅ Selbsttest

  • Warum triggert der Workflow zuerst nur auf ein Testlabel?
  • Warum erstellt der Workflow einen Entwurf statt direkt zu senden?
  • Warum wird die KI-Ausgabe noch einmal geparst und validiert?
  • Welche drei Testfälle brauchst du vor dem Aktivieren?
  • Warum markieren wir die Mail erst am Ende als gelesen?
Antworten 1) Damit nur bewusst ausgewählte Mails verarbeitet werden. · 2) Weil KI-Text menschlich geprüft werden sollte. · 3) Weil KI-Ausgaben trotz Prompt fehlerhaft oder unvollständig sein können. · 4) Normal, dringend, unklar. · 5) Damit Fehler nicht unsichtbar werden.

Du hast jetzt einen KI-Workflow gebaut, der einen realen Arbeitsprozess unterstützt, ohne die Kontrolle abzugeben. Im nächsten Projekt wird die Eingabe schwieriger: PDFs oder Rechnungen müssen erst gelesen, strukturiert und geprüft werden, bevor n8n zuverlässig weiterarbeiten kann.
