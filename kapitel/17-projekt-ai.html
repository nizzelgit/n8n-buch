17 Projekt 5

KI-E-Mail-Assistent

In diesem Projekt liest n8n neue E-Mails, lässt eine Basic LLM Chain die Nachricht klassifizieren, erzeugt einen Antwortentwurf und meldet dringende Fälle an dein Team. Wichtig: Der Workflow sendet keine Antwort automatisch. KI schlägt vor, der Mensch entscheidet.

⏱ ca. 50 Minuten 🎯 Niveau: Mittel bis fortgeschritten 🧩 Voraussetzung: Kapitel 6–12, 14

📋 Was du brauchst

  • Ein Test-Postfach, idealerweise Gmail. Mit IMAP geht es auch, dann heißt der Trigger Email Trigger (IMAP) und die Feldnamen im Output sehen anders aus.
  • Eine Gmail-Credential mit Zugriff auf Lesen, Labels und Entwürfe.
  • Eine Credential für ein Chat Model, etwa für den OpenAI Chat Model- oder den Anthropic Chat Model-Node.
  • Eine Slack-Credential oder einen anderen Benachrichtigungskanal für dringende Fälle.
  • Test-E-Mails. Keine produktiven Kundenmails, bevor du die Klassifikation geprüft hast.
KI ist kein Autopilot Dieses Kapitel baut bewusst einen Assistenten, keinen automatischen Absender. Eine falsch verschickte Antwort holst du nicht zurück, und sie kann dich einen Kunden oder eine Zusage kosten. Der sichere Standard ist: Entwurf erstellen, markieren, Mensch prüft.

Das Ziel

Der Workflow reagiert auf neue ungelesene E-Mails. Er holt den vollständigen Inhalt, kürzt ihn auf das Nötige, fragt eine Basic LLM Chain nach Kategorie, Dringlichkeit und Antwortentwurf, verarbeitet die strukturierte Ausgabe und legt einen Gmail-Entwurf an. Sehr dringende E-Mails werden zusätzlich in Slack gemeldet.

⚡ KI bewertet, n8n entscheidet Nutze KI für Bewertung und Textentwurf, aber lasse n8n die Regeln ausführen: JSON prüfen, IF-Node verzweigen, Entwurf statt Sendung, Label statt endgültiger Entscheidung.

Schritt 1: Testpostfach vorbereiten

Der wichtigste Schutz ist ein klar begrenzter Eingang. Wir lassen den Trigger nicht auf dein ganzes Postfach los. Er sieht nur, was ein eigenes Testlabel trägt.

  1. Gmail-Label anlegen

    Lege in Gmail ein Label n8n-test-ai an.

  2. Test-E-Mail senden

    Sende dir selbst eine E-Mail mit Betreff Bitte Angebot für Workshop und einem kurzen Text.

  3. Label setzen

    Markiere die Test-E-Mail mit n8n-test-ai und lasse sie ungelesen.

Warum ein Label? Trigger auf „alle ungelesenen E-Mails“ sind beim Lernen unnötig riskant. Ein Testlabel ist ein kleiner Zaun: Du entscheidest, welche Mails der Workflow überhaupt sehen darf.

Schritt 2: Workflow und Gmail Trigger anlegen

  1. Neuen Workflow erstellen

    Erstelle einen Workflow und nenne ihn KI-E-Mail-Assistent.

  2. Gmail Trigger hinzufügen

    Klicke auf das große +, suche gmail trigger und wähle Gmail Trigger.

  3. Node benennen

    Nenne ihn Neue E-Mail.

  4. Credential auswählen

    Wähle deine Gmail-Credential oder lege sie wie in Kapitel 12 an.

  5. Ereignis setzen

    Setze Event auf Message Received.

  6. Poll-Zeit setzen

    Unter Poll Times setzt du Mode auf Every X, Value auf 5 und Unit auf Minutes. Im Betrieb darfst du langsamer pollen.

  7. Menge begrenzen

    Setze Max Emails per Poll auf 3. Voreingestellt sind 10, erlaubt sind bis zu 50.

  8. Filter setzen

    Klicke auf Add Filter. Setze Read Status auf Unread emails only und Label Names or IDs auf n8n-test-ai. Beide Felder liegen im Abschnitt Filters, nicht bei den oberen Parametern.

Wenn der Trigger nichts findet Prüfe drei Dinge: Die Mail ist ungelesen, sie hat wirklich das Label n8n-test-ai, und der Trigger nutzt dieselbe Gmail-Credential wie dein Postfach.

Schritt 3: Vollständige E-Mail holen

Der Trigger hat Simplify standardmäßig an und liefert dann nur Kopfzeilen und den Vorschautext aus snippet. Für die KI brauchen wir aber den ganzen Textkörper. Deshalb hängen wir einen Gmail-Node an, der die Nachricht per ID noch einmal holt.

  1. Gmail-Node anhängen

    Ziehe vom Gmail Trigger eine Linie ins Leere, suche gmail und wähle Gmail.

  2. Node benennen

    Nenne ihn E-Mail holen. Unter diesem Namen sprechen wir ihn in den nächsten Schritten an.

  3. Operation wählen

    Setze Resource auf Message und Operation auf Get.

  4. Message ID einsetzen

    Stelle das Feld Message ID auf Expression und trage {{ $json.id }} ein.

  5. Simplify ausschalten

    Schalte Simplify aus. Das ist der entscheidende Klick in diesem Schritt: Mit eingeschaltetem Simplify holt der Node nur die Kopfzeilen und schreibt sie großgeschrieben als Subject und From ins Item, ohne Nachrichtentext. Ausgeschaltet bekommst du subject, from, text, html und headers.

  6. Schritt ausführen

    Führe den Node aus und prüfe rechts, ob Betreff, Absender und Inhalt sichtbar sind. from ist dabei kein einfacher String, sondern ein Objekt. Die lesbare Adresse steht in from.text.

Schritt 4: E-Mail-Text vorbereiten

Signaturen und alte Antwortketten braucht das Modell nicht. Wir bauen ein kompaktes Objekt, das die Basic LLM Chain lesen soll: Betreff, Absender, gekürzter Text, dazu die IDs für die späteren Schritte.

  1. Code-Node anhängen

    Ziehe von E-Mail holen eine Linie ins Leere, suche code und wähle Code.

  2. Node benennen

    Nenne ihn E-Mail vorbereiten.

  3. Modus wählen

    Setze den Modus auf Run Once for Each Item.

  4. Code einfügen

    Füge diesen Code ein. Die ersten drei Zeilen fangen beide Gmail-Varianten ab: subject und from.text kommen aus dem Node ohne Simplify, Subject und From aus dem Node mit Simplify.

  Code · Run Once for Each Item
const subject = $json.subject ?? $json.Subject ?? '';
const from = $json.from?.text ?? $json.from ?? $json.From ?? '';
const rawText = $json.text ?? $json.snippet ?? '';

const cleaned = rawText
  .replace(/On .* wrote:/s, '')
  .replace(/--\s*[\s\S]*$/m, '')
  .replace(/\s+/g, ' ')
  .trim()
  .slice(0, 4000);

return {
  json: {
    message_id: $json.id,
    thread_id: $json.threadId,
    subject,
    from,
    email_text: cleaned
  }
};
⚡ Kontext begrenzen Mehr Text ist nicht automatisch besser. Für Klassifikation und Antwortentwurf reicht oft die aktuelle Nachricht. Alte Zitate und Signaturen erhöhen Kosten und Fehlerwahrscheinlichkeit.

Schritt 5: Basic LLM Chain hinzufügen

Jetzt kommt der KI-Schritt. Wichtig für den Stand Juli 2026: Seit n8n 1.82 gibt es beim AI Agent keine Agent-Typen mehr, jeder AI Agent arbeitet als Tools Agent, und die Doku verlangt mindestens ein verbundenes Tool. Unsere Aufgabe ist reine Klassifikation plus Textentwurf. Dafür passt die Basic LLM Chain besser als ein Agent ohne Werkzeuge.

  1. Basic LLM Chain anhängen

    Ziehe von E-Mail vorbereiten eine Linie ins Leere, suche basic llm chain und wähle Basic LLM Chain.

  2. Keine Tools erzwingen

    Diese Chain bekommt nur den vorbereiteten E-Mail-Text und gibt strukturiertes JSON zurück.

  3. Modell verbinden

    Unter dem Chain-Node hängt ein Anschluss mit dem Namen Model. Beim AI Agent heißt derselbe Anschluss Chat Model; bei der Chain steht dort nur Model. Klicke auf das + darunter und wähle OpenAI Chat Model.

  4. Modell auswählen

    Wähle deine Credential. Im Feld Model steht die Liste der verfügbaren Modelle; n8n 2.32 schlägt beim OpenAI Chat Model gpt-5-mini vor. Nimmst du stattdessen den Anthropic Chat Model-Node, ist claude-sonnet-4-6 die Voreinstellung. Für Einordnen und einen kurzen Entwurf brauchst du kein großes Modell.

  5. Prompt-Quelle setzen

    Setze Source for Prompt (User Message) auf Define below. Die zweite Option heißt Connected Chat Trigger Node und sucht ein Feld chatInput. Das haben wir hier nicht.

  6. Prompt einfügen

    Trage den folgenden Text in das Feld Prompt (User Message) ein.

  Prompt für die Basic LLM Chain
Du bist ein vorsichtiger E-Mail-Assistent.
Analysiere die E-Mail und antworte ausschließlich als gültiges JSON.

Erlaubte Kategorien: sales, support, billing, personal, other.
Erlaubte Dringlichkeit: low, normal, high.

JSON-Schema:
{
  "category": "sales|support|billing|personal|other",
  "urgency": "low|normal|high",
  "summary": "maximal 2 Sätze",
  "reason": "kurze Begründung",
  "draft_subject": "Antwortbetreff",
  "draft_body": "höflicher Antwortentwurf in Du-Form oder neutraler Form"
}

Regeln:
- Keine Fakten erfinden.
- Wenn Informationen fehlen, im Entwurf gezielt nachfragen.
- Bei rechtlichen, medizinischen oder finanziellen Aussagen keine definitive Beratung geben.
- Niemals behaupten, dass eine Aktion bereits erledigt wurde.

E-Mail:
Von: {{ $json.from }}
Betreff: {{ $json.subject }}
Text: {{ $json.email_text }}
Wenn die Chain kein JSON liefert Prüfe zuerst, ob dein Prompt wirklich „ausschließlich gültiges JSON“ verlangt. Die Chain hat außerdem einen Schalter Require Specific Output Format. Schaltest du ihn ein, erscheint unter dem Node ein zusätzlicher Anschluss Output Parser. Dort hängst du den Structured Output Parser ein, setzt Schema Type auf Generate From JSON Example und fügst unter JSON Example genau das Objekt aus dem Prompt oben ein. Achtung, das ändert den nächsten Schritt: Mit Parser landen category, urgency und die übrigen Schlüssel direkt oben im Item, das Feld text gibt es dann nicht mehr. Im Code-Node aus Schritt 6 ersetzt du deshalb die Zeile mit raw samt try-Block durch const parsed = item.json;. Alles darunter bleibt stehen. Diese Prüfung lohnt sich weiterhin, denn auch mit Parser kann ein Modell eine Kategorie erfinden, die du nicht erlaubt hast.

Schritt 6: KI-Ausgabe prüfen und zerlegen

Wir vertrauen der KI-Ausgabe nicht blind. Ein Code-Node versucht, JSON zu parsen, setzt Fallbacks und markiert fehlerhafte Antworten.

Vorher ein Stolperstein, der beim Bauen viel Zeit kostet: Die Basic LLM Chain reicht ihre Eingabe nicht durch. Aus dem Node kommt genau ein Feld heraus, nämlich text. Betreff, Absender und Message-ID sind ab hier weg. Wir holen sie deshalb ausdrücklich über $('E-Mail vorbereiten') zurück und legen sie wieder mit ins Item. Ohne diesen Griff bleiben später der Entwurfsempfänger und das Label leer.

  1. Code-Node anhängen

    Hänge hinter die Basic LLM Chain einen Code-Node und nenne ihn KI-Ausgabe prüfen.

  2. Modus stehen lassen

    Hier brauchen wir Run Once for All Items, den voreingestellten Modus. Nur so kommen wir mit .all() an die Items des früheren Nodes und können sie über den Index zuordnen.

  3. Code einfügen

    Füge diesen Parser ein. Die Basic LLM Chain schreibt ihre Antwort in das Feld text. Die Zeile mit raw prüft trotzdem noch output und response mit, weil ältere Chain-Versionen und der AI Agent andere Namen benutzen.

  Code · Run Once for All Items
const vorbereitet = $('E-Mail vorbereiten').all();

const allowedCategories = ['sales', 'support', 'billing', 'personal', 'other'];
const allowedUrgency = ['low', 'normal', 'high'];

return $input.all().map((item, i) => {
  const quelle = vorbereitet[i]?.json ?? {};
  const raw = item.json.text ?? item.json.output ?? item.json.response ?? '';
  let parsed;

  try {
    parsed = JSON.parse(raw);
  } catch (error) {
    parsed = {
      summary: 'KI-Ausgabe konnte nicht als JSON gelesen werden.',
      reason: String(raw).slice(0, 500),
      parse_error: true
    };
  }

  return {
    json: {
      ...quelle,
      category: allowedCategories.includes(parsed.category) ? parsed.category : 'other',
      urgency: allowedUrgency.includes(parsed.urgency) ? parsed.urgency : 'normal',
      summary: parsed.summary ?? '',
      reason: parsed.reason ?? '',
      draft_subject: parsed.draft_subject ?? ('Re: ' + (quelle.subject ?? '')),
      draft_body: parsed.draft_body ?? 'Danke für deine Nachricht. Ich prüfe das und melde mich.',
      parse_error: Boolean(parsed.parse_error)
    }
  };
});
⚡ KI-Ausgaben sind Eingaben Behandle KI-Antworten wie Daten von außen: parsen, validieren, Defaults setzen. Erst danach darf der Workflow Entscheidungen treffen. Und merk dir die Regel aus diesem Schritt: Was du nach dem KI-Node noch brauchst, holst du dir über $('Node-Name') zurück.

Schritt 7: Entwurf in Gmail erstellen

Jetzt macht der Workflow etwas Nützliches, aber Reversibles: Er legt einen Entwurf an.

  1. Gmail-Node anhängen

    Hänge hinter KI-Ausgabe prüfen einen Gmail-Node.

  2. Operation wählen

    Setze Resource auf Draft und Operation auf Create. Es geht um einen Entwurf, nicht um Senden.

  3. Betreff setzen

    Setze Subject auf {{ $json.draft_subject }}.

  4. Format wählen

    Lass Email Type auf Text stehen. Unser Entwurf ist reiner Text.

  5. Text setzen

    Setze Message auf {{ $json.draft_body }}.

  6. Empfänger setzen

    Ein Feld To gibt es hier nicht, und das ist die Stelle, an der die meisten hängen bleiben. Klicke unten auf Add option und wähle To Email. Trage dort {{ $json.from }} ein. Prüfe bei echten Mails später, ob das Feld nur die Adresse enthält oder auch den Anzeigenamen.

  7. Entwurf in den Thread hängen

    Füge über Add option noch Thread ID hinzu und setze sie auf {{ $json.thread_id }}. Damit sitzt der Entwurf in der richtigen Unterhaltung statt einzeln im Entwurfsordner.

  8. Schritt ausführen

    Führe den Node aus und öffne danach Gmail. Im Entwurfsordner sollte ein neuer Antwortentwurf liegen.

Nicht „Send“ wählen Unter Resource: Message stehen Send, Reply und Send and Wait for Response direkt untereinander. Alle drei schicken die Mail wirklich raus. Für dieses Kapitel bleibst du bei Resource: Draft und Operation: Create.

Schritt 8: Dringende Fälle melden

Jetzt verzweigen wir. Nur E-Mails mit urgency = high gehen zusätzlich in Slack. Alle anderen bekommen allein den Gmail-Entwurf.

  1. IF-Node anhängen

    Hänge hinter KI-Ausgabe prüfen zusätzlich einen IF-Node oder setze ihn vor den Gmail-Entwurf, wenn du die Verzweigung sichtbarer haben willst.

  2. Bedingung setzen

    Links {{ $json.urgency }} eintragen. In der Mitte im Dropdown erst den Datentyp String wählen, dann die Operation is equal to. Rechts high eintragen.

  3. Slack an true-Ausgang hängen

    Hänge an den true-Ausgang einen Slack-Node mit Kanal #inbox-urgent-test.

  4. Slack-Text setzen

    Setze den Text auf die folgende Expression.

  Slack-Text
Dringende E-Mail erkannt
Von: {{ $json.from }}
Betreff: {{ $json.subject }}
Kategorie: {{ $json.category }}
Grund: {{ $json.reason }}

Zusammenfassung:
{{ $json.summary }}

Schritt 9: Label setzen und Mail markieren

Zum Abschluss soll sichtbar sein, dass n8n diese E-Mail bearbeitet hat. Wir setzen ein Label und markieren die Nachricht erst danach als gelesen.

  1. Label vorbereiten

    Lege in Gmail ein Label n8n-ai-draft an.

  2. Gmail-Node anhängen

    Hänge nach dem Entwurf einen weiteren Gmail-Node an.

  3. Aktion wählen

    Setze Resource auf Message und Operation auf Add Label.

  4. Message ID zurückholen

    Der Gmail-Node davor hat einen Entwurf zurückgegeben, nicht unsere ursprüngliche Mail. In $json steht deshalb keine message_id mehr. Trage im Feld Message ID als Expression {{ $('KI-Ausgabe prüfen').item.json.message_id }} ein.

  5. Label wählen

    Unter Label Names or IDs wählst du n8n-ai-draft aus der Liste.

  6. Optional als gelesen markieren

    Füge danach einen Gmail-Node mit Message → Mark as Read hinzu, wieder mit derselben Expression für die Message ID. Mache das erst, wenn Entwurf und Label zuverlässig funktionieren.

Warum erst am Ende als gelesen? Wenn der Workflow vorher scheitert, bleibt die Mail ungelesen und taucht weiter als offene Aufgabe auf. Das ist absichtlich konservativ.

Konkrete Testfälle

  1. Normale Testmail senden

    Sende eine harmlose Anfrage mit dem Testlabel. Erwartung: Entwurf entsteht, keine Slack-Meldung.

  2. Dringende Testmail senden

    Sende eine Mail mit klarer Dringlichkeit, z. B. „Zugang funktioniert nicht, Kundentermin in 30 Minuten“. Erwartung: Entwurf und Slack-Meldung.

  3. Unklare Testmail senden

    Sende eine kurze, mehrdeutige Mail. Erwartung: Der Entwurf fragt nach, statt Details zu erfinden.

  4. Executions prüfen

    Öffne jede Ausführung. Prüfe besonders die Felder category, urgency, summary und draft_body.

  5. Workflow publishen

    Erst wenn alle drei Fälle passen, warte auf Auto-Save und klicke Publish. Lasse das Testlabel zunächst bestehen.

⚡ Teste Grenzfälle, nicht nur Wunschfälle Eine KI-Demo funktioniert fast immer mit perfekten Beispielen. Relevant sind die schlechten Fälle: zu wenig Kontext, widersprüchlicher Text, Dringlichkeit ohne klare Zuständigkeit.

✅ Selbsttest

  • Warum triggert der Workflow zuerst nur auf ein Testlabel?
  • Warum erstellt der Workflow einen Entwurf statt direkt zu senden?
  • Warum wird die KI-Ausgabe noch einmal geparst und validiert?
  • Warum steht hinter der Basic LLM Chain kein Betreff mehr im Item?
  • Welche drei Testfälle brauchst du vor dem Publish?
  • Warum markieren wir die Mail erst am Ende als gelesen?
Antworten 1) Damit nur bewusst ausgewählte Mails verarbeitet werden. · 2) Weil KI-Text menschlich geprüft werden sollte. · 3) Weil KI-Ausgaben trotz Prompt fehlerhaft oder unvollständig sein können. · 4) Weil die Chain nur ihr Feld text ausgibt und die Eingabe nicht durchreicht. · 5) Normal, dringend, unklar. · 6) Damit Fehler nicht unsichtbar werden.
