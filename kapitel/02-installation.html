Installation & Setup

Drei Wege führen zu n8n. Wähle einen. Wechseln kannst du später jederzeit, denn deine Workflows lassen sich exportieren und importieren.

⏱ ca. 16 Minuten 🎯 Niveau: Einstieg 🧩 Du brauchst: Browser, optional Node.js oder Docker

Weg ①: n8n Cloud (empfohlen)

  1. Registrierungsseite öffnen

    Gehe im Browser auf n8n.io und klicke im großen Kopfbereich auf „Get started for free“. Oben rechts in der Navigationsleiste führt der Button „Get Started“ an dieselbe Stelle. Wenn du dir das Suchen sparen willst, tippe direkt app.n8n.cloud/register ein. Du landest auf einer Anmeldemaske.

  2. Konto anlegen

    Gib E-Mail und Passwort ein (oder melde dich mit Google/GitHub an). Das Passwort braucht mindestens acht Zeichen und darin wenigstens eine Ziffer und einen Großbuchstaben. Bestätige anschließend deine E-Mail-Adresse, falls n8n dich dazu auffordert.

  3. Workspace-Namen festlegen

    n8n richtet dir einen eigenen Workspace unter einer Adresse wie dein-name.app.n8n.cloud ein. Das dauert nur Sekunden. Die Testphase läuft 14 Tage und schaltet dir in dieser Zeit die Funktionen des Pro-Plans frei.

  4. Du landest im leeren Editor

    Glückwunsch. Genau diese Oberfläche begleitet dich durch das ganze Buch:

Weg ②: n8n lokal mit npx

Ist auf deinem Rechner Node.js installiert, startest du n8n mit einem einzigen Befehl. Stand Juli 2026 verlangt n8n eine Node.js-Version zwischen 20.19 und 24.x, beide Grenzen eingeschlossen. Öffne ein Terminal und tippe:

  Terminal
# startet n8n und lädt es beim ersten Mal automatisch herunter
npx n8n

Beim ersten Start lädt n8n sich herunter (das kann ein, zwei Minuten dauern). Danach erscheint im Terminal eine Zeile wie diese:

  Terminal-Ausgabe
Editor is now accessible via:
http://localhost:5678

Press "o" to open in Browser.
1 Browser öffnen → 2 localhost:5678 eingeben → 3 Owner-Konto anlegen → 4 fertig

Beim ersten Aufruf legst du ein Owner-Konto an: Name, E-Mail, Passwort. Auch hier gilt die Regel von mindestens acht Zeichen mit Ziffer und Großbuchstabe. Das Konto liegt nur auf deinem Rechner und schützt den Editor. Keine Daten gehen nach außen.

Achtung: Daten weg beim Schließen? Mit npx n8n liegen deine Workflows in einem versteckten Ordner ~/.n8n. Darin steht die Datenbankdatei database.sqlite und dein Verschlüsselungsschlüssel. Solange du den Ordner nicht löschst, bleibt alles erhalten, auch nach einem Neustart. Schließt du nur das Terminal, ist n8n bloß gestoppt und nicht gelöscht. Mit npx n8n startest du es wieder.

Weg ③: Docker (für dauerhaftes Self-Hosting)

Für den Dauerbetrieb ist Docker die praktischste Variante: n8n läuft im Container, getrennt vom Rest deines Systems. Du brauchst dafür eine installierte Docker-Umgebung. Der folgende Befehl startet n8n und legt die Daten in einem benannten Volume ab, damit beim Neustart nichts verloren geht:

  Terminal
# 1) ein Volume für persistente Daten anlegen
docker volume create n8n_data

# 2) n8n starten, Port 5678 nach außen geben
#    Europe/Berlin durch deine eigene Zeitzone ersetzen
docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  -e GENERIC_TIMEZONE="Europe/Berlin" \
  -e TZ="Europe/Berlin" \
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n

Die drei -e-Zeilen sind kein Beiwerk. TZ stellt die Zeitzone des Betriebssystems im Container, auf die sich Systembefehle und Skripte beziehen. GENERIC_TIMEZONE setzt die Zeitzone für zeitgesteuerte Nodes wie den Schedule Trigger. Ohne diese Angabe rechnet n8n mit seinem Standardwert America/New_York, und dein „täglich um 8 Uhr“ feuert um 14 Uhr deutscher Zeit. Meist merkst du das erst, wenn dein Morgenreport nachmittags ankommt. N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true setzt strenge Dateirechte auf die Konfigurationsdatei, in der auch dein Verschlüsselungsschlüssel liegt.

Auch hier öffnest du danach http://localhost:5678. Für einen echten Server kommen später noch eine feste Domain, HTTPS und weitere Umgebungsvariablen dazu. Das vertiefen wir in Kapitel 24 (Deployment).

Task Runner musst du nicht mehr einschalten Seit n8n 2.0 sind Task Runner standardmäßig an. Code-Nodes laufen also von sich aus isoliert, ohne dass du etwas konfigurierst. Die Variable N8N_RUNNERS_ENABLED, die in älteren Anleitungen für 1.x auftaucht, ist ab 2.0 deprecated und im Befehl oben bewusst nicht enthalten. Für die Lernkapitel reicht damit eine normale Einzelinstanz. Interessant wird das Thema erst im Dauerbetrieb: Dort empfiehlt n8n den externen Modus, bei dem die Runner in eigenen Containern starten. Das ordnen wir in Kapitel 25 ein.
Cloud gegen Self-Hosting: der eine echte Unterschied In der Cloud funktionieren Webhooks sofort, denn du bekommst eine öffentlich erreichbare Adresse. Lokal ist dein localhost von außen nicht erreichbar. Für Webhook-Tests brauchst du dann einen Tunnel, den wir in Kapitel 7 zeigen. n8n baut ihn inzwischen über cloudflared, weshalb dafür auch bei einer npm-Installation Docker auf dem Rechner liegen muss. Für die ersten Kapitel spielt das alles keine Rolle.

Was du beim ersten Login siehst

Egal welcher Weg: Nach dem allerersten Start fragt n8n ein paar Dinge ab (Owner-Konto, optional eine kurze Umfrage „Wofür nutzt du n8n?“). Danach bist du im Editor. Vielleicht begrüßt dich ein leerer Canvas mit dem großen + wie in Abb. 2.1, vielleicht auch ein Begrüßungsfenster mit zwei großen Buttons. Nimm dort den, der einen leeren Workflow anlegt; in der englischen Oberfläche heißt er Start from Scratch. Ein dritter Fall ist die Übersichtsseite mit der Workflow-Liste. Dann klickst du dort auf Create Workflow. Manchmal schiebt n8n vorher noch eine kurze Tour dazwischen; die kannst du gefahrlos wegklicken.

✅ Checkliste: Bereit für Kapitel 3?

  • n8n läuft (Cloud-URL oder localhost:5678 öffnet sich).
  • Du siehst den Editor mit dem leeren Canvas.
  • Oben rechts erkennst du den Auto-Save-Status und den Publish-Button.

Steht das? Perfekt. Im nächsten Kapitel nehmen wir diese Oberfläche systematisch auseinander: jeden Bereich und jeden wichtigen Button. Danach fühlst du dich dort nie wieder verloren.
