Installation & Setup

Es gibt drei Wege, n8n zum Laufen zu bringen. Du wählst einen davon. Falsch entscheiden kannst du dich nicht: Deine Workflows lassen sich jederzeit exportieren und auf einem anderen Weg wieder importieren.

ca. 16 Minuten Niveau: Einstieg Du brauchst: Browser, optional Node.js oder Docker

Welcher Weg ist der richtige für dich?

Kurz zu den Begriffen: Cloud heißt, n8n läuft auf den Servern der n8n-Firma und du nutzt es einfach im Browser. Lokal heißt, n8n läuft direkt auf deinem eigenen Rechner. Docker ist ein Programm, das Anwendungen in einer abgeschotteten Box (einem „Container“) laufen lässt.

WegAufwandFür wen?
① n8n CloudNull Installation, Testphase Empfohlen zum Starten & für dieses Buch
② Lokal mit npxEin Befehl, läuft auf deinem RechnerWer Node.js hat und nichts in der Cloud will
③ DockerEin Befehl, läuft dauerhaft im ContainerWer es ernsthaft selbst hosten will
Empfehlung fürs Buch Wenn du einfach loslegen willst: Nimm ① Cloud. Du musst nichts installieren und siehst exakt die Oberfläche aus diesem Buch. Die Wege ② und ③ („Self-Hosting“, also selbst betreiben) zeige ich für später. Diese Abschnitte kannst du jetzt überspringen und gleich zu Kapitel 3 gehen.

Weg ①: n8n Cloud (empfohlen)

  1. Registrierungsseite öffnen

    Öffne deinen Browser und tippe in die Adresszeile n8n.io. Klicke dann im großen Kopfbereich der Seite auf den Button „Get started for free“ (auf Deutsch: kostenlos loslegen). Falls du ihn nicht findest: Oben rechts in der Navigationsleiste führt der Button „Get Started“ an dieselbe Stelle. Noch schneller geht es, wenn du direkt app.n8n.cloud/register in die Adresszeile tippst. In allen Fällen landest du auf einer Anmeldemaske.

  2. Konto anlegen

    Gib deine E-Mail-Adresse und ein Passwort ein. Alternativ meldest du dich mit einem Klick über dein Google- oder GitHub-Konto an. Das Passwort braucht mindestens acht Zeichen, darunter eine Ziffer und einen Großbuchstaben. Vielleicht schickt n8n dir danach eine Bestätigungs-Mail. Dann klickst du auf den Link darin.

  3. Workspace-Namen festlegen

    n8n richtet dir jetzt einen eigenen Workspace ein, also deinen persönlichen Arbeitsbereich im Netz. Er bekommt eine Adresse wie dein-name.app.n8n.cloud. Das Einrichten dauert nur Sekunden. Die Testphase läuft 14 Tage. In dieser Zeit kannst du die Funktionen des Pro-Plans kostenlos nutzen.

  4. Du landest im leeren Editor

    Glückwunsch, das war schon alles. Du siehst jetzt eine fast leere Fläche mit einem großen + in der Mitte. Genau diese Oberfläche begleitet dich durch das ganze Buch:

Weg ②: n8n lokal mit npx

Dieser Weg setzt voraus, dass auf deinem Rechner Node.js installiert ist. Node.js ist eine kostenlose Laufzeitumgebung, mit der JavaScript-Programme wie n8n auf deinem Rechner laufen. Stand Juli 2026 verlangt n8n eine Node.js-Version zwischen 20.19 und 24.x, beide Grenzen eingeschlossen. Öffne dann ein Terminal, also das Fenster, in das du Textbefehle eintippst (auf dem Mac heißt das Programm „Terminal“, unter Windows „PowerShell“). Tippe dort diesen Befehl ein und drücke Enter:

  Terminal
# startet n8n und lädt es beim ersten Mal automatisch herunter
npx n8n

Beim ersten Start lädt sich n8n herunter. Das kann ein bis zwei Minuten dauern, in denen im Terminal viel Text vorbeiläuft. Das ist normal, du musst nichts tun. Am Ende erscheint eine Zeile wie diese:

  Terminal-Ausgabe
Editor is now accessible via:
http://localhost:5678

Press "o" to open in Browser.

Sobald du diese Zeile siehst, läuft n8n. Du kannst jetzt einfach die Taste o drücken, dann öffnet sich der Browser von selbst. Oder du machst es von Hand:

1 Browser öffnen → 2 localhost:5678 eingeben → 3 Owner-Konto anlegen → 4 fertig

localhost:5678 bedeutet übrigens: „mein eigener Rechner, Tür Nummer 5678“. Die Adresse funktioniert nur bei dir, sie führt nicht ins Internet. Beim ersten Aufruf legst du ein Owner-Konto an (Owner = Besitzer dieser n8n-Installation): Name, E-Mail, Passwort. Auch hier gilt die Regel von mindestens acht Zeichen mit Ziffer und Großbuchstabe. Das Konto liegt nur auf deinem Rechner und schützt den Editor. Keine Daten gehen nach außen. Danach siehst du denselben leeren Editor wie in Abb. 2.1.

Achtung: Daten weg beim Schließen? Keine Sorge. Mit npx n8n liegen deine Workflows in einem versteckten Ordner ~/.n8n in deinem Benutzerverzeichnis. Darin stehen die Datenbankdatei database.sqlite und dein Verschlüsselungsschlüssel. Solange du diesen Ordner nicht löschst, bleibt alles erhalten, auch nach einem Neustart des Rechners. Schließt du nur das Terminal, ist n8n bloß gestoppt, nicht gelöscht. Mit npx n8n startest du es wieder.

Weg ③: Docker (für dauerhaftes Self-Hosting)

Für den Dauerbetrieb ist Docker die praktischste Variante. n8n läuft dann in einem Container, getrennt vom Rest deines Systems. Voraussetzung: Docker ist auf deinem Rechner installiert. Öffne dann ein Terminal und führe die folgenden zwei Befehle nacheinander aus. Der erste legt ein Volume an, einen dauerhaften Speicherplatz für deine Daten. Der zweite startet n8n. So geht beim Neustart nichts verloren:

  Terminal
# 1) ein Volume für persistente Daten anlegen
docker volume create n8n_data

# 2) n8n starten, Port 5678 nach außen geben
#    Europe/Berlin durch deine eigene Zeitzone ersetzen
docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  -e GENERIC_TIMEZONE="Europe/Berlin" \
  -e TZ="Europe/Berlin" \
  -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true \
  -v n8n_data:/home/node/.n8n \
  docker.n8n.io/n8nio/n8n

Die drei Zeilen mit -e setzen sogenannte Umgebungsvariablen, also Einstellungen, die du n8n beim Start mitgibst. Lass keine davon weg. TZ stellt die Zeitzone des Betriebssystems im Container ein. Darauf beziehen sich Systembefehle und Skripte. GENERIC_TIMEZONE setzt die Zeitzone für zeitgesteuerte Nodes wie den Schedule Trigger. Ohne diese Angabe rechnet n8n mit seinem Standardwert America/New_York. Dein „täglich um 8 Uhr“ feuert dann um 14 Uhr deutscher Zeit. Meist merkst du das erst, wenn dein Morgenreport nachmittags ankommt. N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true setzt strenge Dateirechte auf die Konfigurationsdatei, in der auch dein Verschlüsselungsschlüssel liegt.

Sobald der zweite Befehl läuft, öffnest du im Browser http://localhost:5678, legst wie bei Weg ② dein Owner-Konto an und bist im Editor. Für einen echten Server kommen später noch eine feste Domain, HTTPS und weitere Umgebungsvariablen dazu. Das vertiefen wir in Kapitel 24 (Deployment).

Task Runner musst du nicht mehr einschalten In älteren Anleitungen für n8n 1.x taucht die Variable N8N_RUNNERS_ENABLED auf. Die brauchst du nicht mehr. Seit n8n 2.0 sind Task Runner standardmäßig an, Code-Nodes laufen also von sich aus isoliert und sicher. Die Variable ist ab 2.0 deprecated (veraltet) und fehlt im Befehl oben deshalb mit Absicht. Für die Lernkapitel reicht eine normale Einzelinstanz. Erst im Dauerbetrieb wird das Thema interessant: Dort empfiehlt n8n den externen Modus, bei dem die Runner in eigenen Containern starten. Das ordnen wir in Kapitel 25 ein.
Cloud gegen Self-Hosting: der eine echte Unterschied In der Cloud funktionieren Webhooks (Nachrichten, die andere Dienste an deinen Workflow schicken) sofort, denn du bekommst eine öffentlich erreichbare Adresse. Lokal ist dein localhost von außen nicht erreichbar. Für Webhook-Tests brauchst du dann einen Tunnel, den wir in Kapitel 7 zeigen. n8n baut ihn inzwischen über cloudflared, weshalb dafür auch bei einer npm-Installation Docker auf dem Rechner liegen muss. Für die ersten Kapitel spielt das alles keine Rolle.

Was du beim ersten Login siehst

Egal welcher Weg: Nach dem allerersten Start fragt n8n ein paar Dinge ab (Owner-Konto, optional eine kurze Umfrage „Wofür nutzt du n8n?“). Danach bist du im Editor. Wundere dich nicht, wenn dein Bildschirm etwas anders aussieht als hier beschrieben. Es gibt drei mögliche Varianten, und alle sind in Ordnung. Erste Variante: ein leerer Canvas (die große Arbeitsfläche) mit dem großen + wie in Abb. 2.1. Zweite Variante: ein Begrüßungsfenster mit zwei großen Buttons. Klicke dort auf den Button, der einen leeren Workflow anlegt; in der englischen Oberfläche heißt er Start from Scratch. Dritte Variante: eine Übersichtsseite mit einer Workflow-Liste. Dann klickst du dort auf Create Workflow. Manchmal schiebt n8n vorher noch eine kurze Tour dazwischen. Die kannst du gefahrlos wegklicken.

Checkliste: Bereit für Kapitel 3?

  • n8n läuft (Cloud-URL oder localhost:5678 öffnet sich).
  • Du siehst den Editor mit dem leeren Canvas.
  • Oben rechts erkennst du den Auto-Save-Status und den Publish-Button.

Kannst du alle drei Punkte abhaken? Dann ist dieses Kapitel erledigt. Im nächsten nehmen wir die Oberfläche auseinander, jeden Bereich und jeden wichtigen Button, damit du später nicht suchen musst.
