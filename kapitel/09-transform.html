9 Bausteine im Detail

Daten transformieren: Set, Code & Filter

Daten kommen selten genau in der Form, die du brauchst. Mal sind Felder zu viel, mal fehlt eins, mal soll etwas berechnet oder aussortiert werden. Dafür gibt es drei Werkzeuge. In 90 % der Fälle reicht schon das erste.

ca. 20 Minuten Niveau: Mittel Voraussetzung: Kapitel 5 & 6

Was du mitbringen solltest

  • Items und das „läuft pro Item“-Prinzip (Kapitel 5).
  • Expressions (Kapitel 6): In Set und Filter brauchst du sie ständig.
  • Den Edit-Fields-Node hast du in Kapitel 4 schon kurz benutzt.

Drei Werkzeuge, eine klare Rangfolge

Erst no-code, dann Code Greif zum Code-Node erst, wenn es mit Set, Filter & Co. wirklich nicht geht. Einen visuellen Node versteht auch jemand, der kein JavaScript kann, und nach jedem „▶ Schritt ausführen“ siehst du im Output-Panel sofort, was er getan hat. Sehr vieles, was nach „da brauche ich Code“ aussieht, löst eine Expression in einem Set-Node.

Edit Fields (Set): das Arbeitspferd

Der Set-Node baut ein neues, sauberes Objekt aus dem, was hereinkommt. Du legst Felder an und gibst jedem einen Wert, fest getippt oder als Expression. Danach entscheidest du, ob die übrigen Eingangsfelder mitlaufen oder wegfallen.

  1. Node anlegen & öffnen

    Zieh vom letzten Node eine Linie ins Leere und wähl „Edit Fields (Set)“ aus der Liste. Öffne den Node mit einem Doppelklick. Ganz oben steht das Auswahlfeld Mode (Modus). Es steht auf Manual Mapping, also „Felder von Hand anlegen“. Die zweite Möglichkeit im selben Dropdown heißt JSON; dort tippst du das Ausgabe-Objekt selbst als JSON. Wir bleiben bei Manual Mapping.

  2. Felder hinzufügen

    Darunter siehst du den Bereich „Fields to Set“ (die Felder, die der Node setzen soll). Klick dort auf „Add Field“. Ein neuer Eintrag erscheint, mit drei Angaben: Unter Name legst du fest, wie das Feld heißen soll (z. B. stadt), unter Type die Art des Werts (String = Text, Number = Zahl, Boolean = wahr/falsch …) und unter Value den Wert selbst. Beim Wert schaltest du wie gewohnt zwischen Fest (engl. Fixed) und Expression um.

  3. Nur gesetzte Felder behalten

    Scroll ganz nach unten. Dort sitzt der Schalter „Include Other Input Fields“ („übrige Eingangsfelder mitnehmen“). Ab Werk ist er aus. Dann enthält die Ausgabe nur deine neuen Felder. Genau so wirst du den Ballast los. Schaltest du ihn ein, erscheint darunter „Input Fields to Include“ mit den Möglichkeiten All (alle), Selected (nur ausgewählte) und All Except (alle außer).

Sauberes Objekt = ruhiger Workflow Ich hänge in fast jedem Workflow direkt hinter den ersten HTTP-Request so einen Set-Node. Reduzier früh auf die Felder, die du wirklich weitergibst, dann musst du dich später nie wieder durch das große Roh-JSON wühlen.

Filter: Items aussortieren

Der Filter-Node lässt nur die Items durch, die eine Bedingung erfüllen. Der Rest wird verworfen. Bekommt er fünf Items und drei erfüllen die Regel, kommen drei heraus.

  1. Node anlegen & öffnen

    Häng den Node „Filter“ an und öffne ihn. Du siehst einen Bereich „Conditions“ (Bedingungen). Hier legst du die Regel fest, die ein Item erfüllen muss, um durchzukommen.

  2. Eine Bedingung bauen

    Eine Bedingung hat drei Teile. Links steht der Wert, den du prüfen willst, per Expression, z. B. {{ $json.tempC }}. In der Mitte wählst du den Operator, also die Art des Vergleichs, z. B. is greater than („ist größer als“). Rechts steht der Vergleichswert, z. B. 20. Welche Operatoren dir angeboten werden, hängt am gewählten Datentyp: bei Zahlen is greater than, bei Text contains („enthält“), bei Datum is after („liegt nach“).

  3. Mehrere Bedingungen kombinieren

    Mit AND (und) bzw. OR (oder) verknüpfst du mehrere Bedingungen, z. B. „tempC > 20 UND windKmh < 15“.

Wenn plötzlich gar nichts durchkommt Dann passt meist der Datentyp nicht. Der Text "20" ist für n8n etwas anderes als die Zahl 20, und die Bedingung greift nicht. Direkt unter den Conditions sitzt dafür der Schalter „Convert types where required“, und der steht anfangs auf aus. Schalte ihn ein, dann rechnet n8n den Wert vor dem Vergleich in den passenden Typ um.
Filter vs. IF Filter wirft Nicht-Treffer einfach weg (ein Ausgang). Brauchst du beide Gruppen, Treffer und Nicht-Treffer in getrennten Zweigen, dann nimm den IF-Node (nächstes Kapitel).

Code: der letzte Ausweg

Wenn wirklich kein No-code-Node reicht, schreibst du im Code-Node ein paar Zeilen Programmcode. Keine Sorge: Die Beispiele hier kannst du einfach abtippen. Oben im Node wählst du unter Language (Programmiersprache) zwischen JavaScript und Python. Wir bleiben bei JavaScript. (Seit n8n 2.0 läuft Python nativ über die Task Runner; auf n8n Cloud kannst du dort keine Python-Bibliotheken importieren.) Direkt darunter steht der Mode, und der ist die eigentlich wichtige Entscheidung:

  • Run Once for All Items: Dein Code läuft einmal und bekommt alle Items über $input.all(). Du gibst eine Liste von Items zurück.
  • Run Once for Each Item: Dein Code läuft pro Item; du arbeitest mit $json und gibst ein Objekt zurück.
  Code · Modus „Run Once for Each Item“
// Vor- und Nachname zu einem Anzeigenamen zusammenbauen
return {
  name: $json.vorname + ' ' + $json.nachname,
  initialen: ($json.vorname[0] + $json.nachname[0]).toUpperCase()
};
Der Code-Node sitzt seit n8n 2.0 im Sandkasten

Ab Version 2.0 laufen Code-Nodes standardmäßig in sogenannten Task Runnern, also in einem abgeschotteten Extra-Prozess neben n8n. Im Alltag merkst du davon nichts. Erst wenn du etwas versuchst, was dort verboten ist, meldet sich n8n mit einem Fehler:

• Keine Umgebungsvariablen. process.env im Code-Node und $env in Expressions sind ab 2.0 blockiert. Auf einer selbst gehosteten Instanz kannst du das mit N8N_BLOCK_ENV_ACCESS_IN_NODE=false wieder öffnen. n8n rät davon ab: Zugangsdaten gehören in Credentials.

• Keine Module ohne Freigabe. Auf n8n Cloud stehen dir das Node.js-Modul crypto und das npm-Paket moment zur Verfügung, sonst nichts. Selbst gehostet gibst du Module über NODE_FUNCTION_ALLOW_BUILTIN und NODE_FUNCTION_ALLOW_EXTERNAL frei, und zwar an den Task Runnern, nicht am n8n-Hauptprozess.

• Kein HTTP, keine Dateien, keine Credentials. Willst du eine API rufen, nimm den HTTP-Request-Node. Willst du eine Datei lesen, nimm „Read/Write Files from Disk“.

Wenn etwas schiefgeht

• „Code doesn't return items properly“? Im Modus „All Items“ musst du eine Liste zurückgeben (return [...]), nicht ein einzelnes Objekt.

• Falscher Modus. Greifst du auf $json zu, brauchst du „Run Once for Each Item“. Willst du alle Items auf einmal sehen, nimm „All Items“ mit $input.all().

• „Cannot find module …“? Das Modul ist nicht freigegeben. Auf n8n Cloud kannst du daran nichts ändern und musst ohne auskommen. Selbst gehostet trägst du es in NODE_FUNCTION_ALLOW_BUILTIN bzw. NODE_FUNCTION_ALLOW_EXTERNAL ein.

Mini-Übung: Wetterdaten auf das Wesentliche eindampfen

Wir nehmen wieder den Wetter-Workflow und hängen hinter „Wetter holen“ einen Set-Node, der ein sauberes Objekt baut.

  1. Set-Node anhängen

    Zieh vom kleinen Punkt rechts am HTTP-Node eine Linie ins Leere. Wähl „Edit Fields (Set)“ aus der Liste und öffne den Node.

  2. Drei Felder anlegen

    Klick dreimal auf „Add Field“ und trag ein: String stadt = Berlin · Number tempC = {{ Math.round($json.current.temperature_2m) }} · Number windKmh = {{ Math.round($json.current.wind_speed_10m) }}. Die beiden Zahlenfelder brauchen den Expression-Modus.

  3. „Include Other Input Fields“ ausgeschaltet lassen

    Der Schalter steht ohnehin auf aus. Schau trotzdem kurz nach, damit wirklich nur deine drei Felder übrig bleiben.

  4. Ausführen & prüfen

    Klick auf „▶ Schritt ausführen“. Im Output-Panel steht jetzt ein knappes Objekt { stadt, tempC, windKmh }. Wenn du das siehst, hat alles geklappt. Viel angenehmer als das große Roh-JSON.

Selbsttest

  • Welches der drei Werkzeuge nimmst du zuerst, und warum?
  • Wie sorgst du dafür, dass ein Set-Node nur deine neuen Felder ausgibt?
  • Du hast 8 Items, der Filter lässt 3 durch. Was passiert mit den anderen 5?
  • Welcher Code-Modus gibt eine Liste zurück, welcher ein einzelnes Objekt?
  • Du brauchst Treffer und Nicht-Treffer getrennt: Filter oder IF?
  • Warum kommst du im Code-Node seit n8n 2.0 nicht mehr an process.env?
Antworten 1) Edit Fields (Set): visuell, leicht zu testen, deckt das meiste ab. · 2) „Include Other Input Fields“ aus lassen, das ist der Standard. · 3) Sie werden verworfen (Filter hat nur einen Ausgang). · 4) „Run Once for All Items“ → Liste; „Run Once for Each Item“ → ein Objekt. · 5) IF (zwei Ausgänge). · 6) Der Code-Node läuft im Task Runner, und der Zugriff auf Umgebungsvariablen ist dort standardmäßig blockiert.

Du kannst Daten jetzt holen, senden und umformen. Als Nächstes bringen wir Logik in den Workflow: verzweigen mit IF und Switch, Zweige wieder zusammenführen mit Merge. Und wir klären, wann du wirklich eine Schleife brauchst. Spoiler: seltener, als du denkst.
