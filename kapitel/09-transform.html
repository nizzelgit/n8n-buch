9 Bausteine im Detail

Daten transformieren: Set, Code & Filter

Daten kommen selten genau in der Form, die du brauchst. Mal sind Felder zu viel, mal fehlt eins, mal soll etwas berechnet oder aussortiert werden. Dafür gibt es drei Werkzeuge — und in 90 % der Fälle reicht schon das erste.

⏱ ca. 20 Minuten 🎯 Niveau: Mittel 🧩 Voraussetzung: Kapitel 5 & 6

📋 Was du mitbringen solltest

  • Items und das „läuft pro Item"-Prinzip (Kapitel 5).
  • Expressions (Kapitel 6) — sie sind in Set und Filter überall im Einsatz.
  • Den Edit-Fields-Node hast du in Kapitel 4 schon kurz benutzt.

Drei Werkzeuge, eine klare Rangfolge

⚡ Erst no-code, dann Code Greif zum Code-Node erst, wenn es mit Set, Filter & Co. wirklich nicht geht. Visuelle Nodes sind leichter zu lesen, zu testen und für andere nachvollziehbar. Sehr vieles, was nach „da brauche ich Code" aussieht, löst eine Expression in einem Set-Node.

Edit Fields (Set): das Arbeitspferd

Der Set-Node baut ein neues, sauberes Objekt aus dem, was hereinkommt. Du legst Felder an, gibst jedem einen Wert (fest oder Expression) — und entscheidest, ob die übrigen Eingangsfelder mitlaufen oder wegfallen.

  1. Node anlegen & öffnen

    Häng „Edit Fields (Set)" an und öffne ihn. Mode steht auf Manual Mapping.

  2. Felder hinzufügen

    Klick „Add Field". Wähle links den Typ (String, Number, Boolean …), tippe den Namen und setze rechts den Wert — per Reiter „Fest" oder „Expression".

  3. Nur gesetzte Felder behalten

    Ganz unten gibt es „Include Other Input Fields". Lässt du es aus, enthält die Ausgabe nur deine neuen Felder — perfekt, um Ballast loszuwerden.

💡 Sauberes Objekt = ruhiger Workflow Reduziere früh auf die Felder, die du wirklich weitergibst. Das macht spätere Nodes übersichtlicher und Fehler seltener — du siehst auf einen Blick, womit du arbeitest.

Filter: Items aussortieren

Der Filter-Node lässt nur die Items durch, die eine Bedingung erfüllen — der Rest wird verworfen. Bekommt er fünf Items und drei erfüllen die Regel, kommen drei heraus.

  1. Node anlegen & öffnen

    „Filter" anhängen und öffnen. Du siehst einen Bereich „Conditions".

  2. Eine Bedingung bauen

    Links der Wert (per Expression, z. B. {{ $json.tempC }}), in der Mitte der Operator (z. B. is greater than), rechts der Vergleichswert (z. B. 20).

  3. Mehrere Bedingungen kombinieren

    Mit AND/OR verknüpfst du Bedingungen, z. B. „tempC > 20 UND windKmh < 15".

Filter vs. IF Filter wirft Nicht-Treffer einfach weg (ein Ausgang). Brauchst du beide Gruppen — Treffer und Nicht-Treffer in getrennten Zweigen — nimm den IF-Node (nächstes Kapitel).

Code: der letzte Ausweg (mit Bedacht)

Wenn wirklich kein no-code-Node reicht, schreibst du im Code-Node ein paar Zeilen JavaScript (oder Python). Wichtig ist der Modus oben:

  • Run Once for All Items: Dein Code läuft einmal und bekommt alle Items über $input.all(). Du gibst eine Liste von Items zurück.
  • Run Once for Each Item: Dein Code läuft pro Item; du arbeitest mit $json und gibst ein Objekt zurück.
  Code · Modus „Run Once for Each Item"
// Vor- und Nachname zu einem Anzeigenamen zusammenbauen
return {
  name: $json.vorname + ' ' + $json.nachname,
  initialen: ($json.vorname[0] + $json.nachname[0]).toUpperCase()
};
Wenn etwas schiefgeht

• „Code doesn't return items properly"? Im Modus „All Items" musst du eine Liste zurückgeben (return [...]), nicht ein einzelnes Objekt.

• Falscher Modus. Greifst du auf $json zu, brauchst du „Run Once for Each Item". Willst du alle Items auf einmal sehen, nimm „All Items" mit $input.all().

Mini-Übung: Wetterdaten auf das Wesentliche eindampfen

Wir nehmen wieder den Wetter-Workflow und hängen hinter „Wetter holen" einen Set-Node, der ein sauberes Objekt baut.

  1. Set-Node anhängen

    Vom HTTP-Node eine Linie ziehen, „Edit Fields (Set)" wählen, öffnen.

  2. Drei Felder anlegen

    String stadt = Berlin · Number tempC = {{ Math.round($json.current.temperature_2m) }} · Number windKmh = {{ Math.round($json.current.wind_speed_10m) }}.

  3. „Include Other Input Fields" ausschalten

    Damit nur deine drei Felder übrig bleiben.

  4. Ausführen & prüfen

    „▶ Schritt ausführen": Im Ausgang steht jetzt ein knappes Objekt { stadt, tempC, windKmh } — viel angenehmer als das große Roh-JSON.

✅ Selbsttest

  • Welches der drei Werkzeuge nimmst du zuerst — und warum?
  • Wie sorgst du dafür, dass ein Set-Node nur deine neuen Felder ausgibt?
  • Du hast 8 Items, der Filter lässt 3 durch — was passiert mit den anderen 5?
  • Welcher Code-Modus gibt eine Liste zurück, welcher ein einzelnes Objekt?
  • Du brauchst Treffer und Nicht-Treffer getrennt — Filter oder IF?
Antworten 1) Edit Fields (Set) — visuell, leicht zu testen, deckt das meiste ab. · 2) „Include Other Input Fields" ausschalten. · 3) Sie werden verworfen (Filter hat nur einen Ausgang). · 4) „Run Once for All Items" → Liste; „Run Once for Each Item" → ein Objekt. · 5) IF (zwei Ausgänge).

Du kannst Daten jetzt holen, senden und umformen. Als Nächstes bringen wir Logik in den Ablauf: verzweigen mit IF und Switch, Zweige wieder zusammenführen mit Merge — und klären, wann du wirklich eine Schleife brauchst (Spoiler: seltener, als du denkst).
