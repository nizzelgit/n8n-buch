Flow-Logik: IF, Switch, Merge & Loops

Bisher liefen unsere Workflows schnurgerade von links nach rechts. Jetzt bringen wir Entscheidungen hinein: verschiedene Wege je nach Daten, getrennte Zweige wieder zusammenführen. Und wir klären die Frage, wann du wirklich eine Schleife brauchst.

⏱ ca. 22 Minuten 🎯 Niveau: Mittel 🧩 Voraussetzung: Kapitel 5, 6 & 9

📋 Was du mitbringen solltest

  • Das „läuft pro Item“-Prinzip (Kapitel 5). Es erklärt, warum du Schleifen selten brauchst.
  • Bedingungen aus Kapitel 6 (>, ||, …) und dem Filter (Kapitel 9).

IF: die Weiche mit zwei Ausgängen

Der IF-Node prüft eine Bedingung und schickt jedes Item in einen von zwei Ausgängen: true (Bedingung erfüllt) oder false (nicht erfüllt). Anders als der Filter wirft er nichts weg. Beide Gruppen laufen in getrennten Zweigen weiter. Im Node-Panel steht er übrigens als If, nicht in Großbuchstaben.

  1. IF anlegen & öffnen

    Im Node-Panel nach „If“ suchen, anhängen, öffnen. Der Bereich Conditions sieht aus wie beim Filter (Kapitel 9). Weitere Zeilen legst du mit Add Condition an.

  2. Bedingung setzen

    Links den Wert {{ $json.tempC }} eintragen. In der Mitte klappst du das Dropdown auf und wählst erst den Datentyp Number, dann die Operation is greater than. Rechts 20 eintragen.

  3. Die zwei Ausgänge verbinden

    Vom oberen Ausgang (true) ziehst du zum „warm“-Zweig, vom unteren (false) zum „kühl“-Zweig. Fertig ist die Verzweigung.

Ein Stolperstein beim IF-Node: Der Vergleich ist typstreng. Kommt tempC als Text aus der API, bricht der Node mit einer Typmeldung ab, statt still false zu liefern. Du hast zwei Auswege. Entweder du wandelst den Wert vorher um (Kapitel 9), oder du schaltest im Node den Regler Convert types where required ein. In der Doku steht dieselbe Einstellung stellenweise noch unter ihrem alten Namen Less Strict Type Validation.

Switch: die Weiche mit vielen Ausgängen

Brauchst du mehr als zwei Wege, nimm den Switch. Du legst mit Add Routing Rule mehrere Routing Rules an, und jede Regel bekommt ihren eigenen Ausgang. So sortierst du z. B. nach Kategorie, Status oder Sprache. Schaltest du in einer Regel Rename Output ein, trägt der Ausgang statt einer Nummer den Namen, den du unter Output Name vergibst.

Switch-ModusSortiert nach …
Rulesfrei definierten Bedingungen: ein Ausgang pro Regel (wie mehrere IFs)
Expressioneinem Index, den du berechnest. Du setzt Number of Outputs und schreibst in Output Index eine Expression, die eine Zahl ab 0 zurückgibt (für Fortgeschrittene)
Switch = IF mit mehr Türen Denk an Switch als IF mit beliebig vielen Ausgängen. Zwei Wege → IF. Drei oder mehr → Switch. Für alles, was zu keiner Regel passt, gibt es einen Fallback-Ausgang. Du holst ihn dir über Options → Add option → Fallback Output → Extra Output. Lässt du die Einstellung auf None, verschwinden nicht passende Items lautlos.

Merge: getrennte Zweige zusammenführen

Hast du verzweigt, willst du oft später wieder zusammenführen. Das macht der Merge-Node. Er startet mit zwei Eingängen und einem Ausgang. Brauchst du mehr, setzt du das Feld Number of Inputs höher. Das geht in jedem Modus außer Combine. Combine vergleicht immer genau zwei Listen.

Merge-ModusMacht
Appendhängt die Listen einfach hintereinander (erst Input 1, dann Input 2)
Combine → Combine By: Matching Fieldsverbindet Items, die in einem Feld übereinstimmen (z. B. gleiche id)
Combine → Combine By: Positionverbindet das 1. mit dem 1., das 2. mit dem 2. Item usw.
Combine → Combine By: All Possible Combinationspaart jedes Item aus Input 1 mit jedem aus Input 2 (Kreuzprodukt)
SQL Querydu schreibst den Join selbst; die Eingänge heißen in der Abfrage input1, input2 und so weiter
Choose Branchwartet auf beide Eingänge und reicht danach nur die Daten eines Eingangs unverändert weiter

Die drei Combine By-Varianten stehen im Node nicht direkt unter Mode. Erst Mode auf Combine stellen, danach erscheint das zweite Dropdown Combine By. Beim ersten Mal habe ich dort lange gesucht.

⚡ IF + Merge sind die Arbeitspferde Verzweigen mit IF, später mit Merge wieder zusammen: Dieses Paar deckt fast alle „mal so, mal so“-Abläufe ab. Switch nur, wenn es wirklich mehr als zwei Wege sind.

Loops: meistens brauchst du sie nicht

Der häufigste Anfänger-Reflex: „Ich habe eine Liste, ich brauche eine Schleife.“ Fast nie! Erinnere dich an Kapitel 5: Ein Node läuft automatisch pro Item. Hast du 100 Items, läuft der nächste Node 100-mal, ganz ohne Schleife.

⚡ Die Regel zuerst Willst du „für jede Zeile etwas tun“, sorg einfach dafür, dass jede Zeile ein Item ist (z. B. „Split Out“ aus Kapitel 9). Den Rest macht n8n durch Wiederholung pro Item von selbst.

Eine echte Schleife brauchst du nur in Sonderfällen. Im Node-Panel heißt sie „Loop Over Items (Split in Batches)“, auf dem Canvas trägt der Node danach den kurzen Namen „Loop Over Items“. Diese Fälle gibt es:

  • Batching: Eine API erlaubt nur 10 Einträge pro Aufruf. Du setzt Batch Size auf 10 und arbeitest die Liste in Häppchen ab.
  • Rate-Limits / Pausen: du willst zwischen den Durchläufen warten (Kapitel 23).
  • Zustand über Runden: jeder Durchlauf baut auf dem vorherigen auf.

Diese Reihenfolge musst du dir merken: Am Node sitzt done oben und loop darunter. So ist es seit der dritten Version des Nodes, die im Herbst 2023 kam. Ältere Screenshots und Videos zeigen die umgekehrte Belegung, und genau daher kommt die Verwechslung. Läuft dein Verarbeitungsschritt gar nicht oder nur ein einziges Mal ganz am Ende, hängt er am falschen Ausgang.

Wenn etwas schiefgeht

• Schleife bleibt nach dem ersten Batch stehen? Der verarbeitende Zweig muss zurück zum Loop-Node führen, sonst wird nicht weitergezählt. Prüfe, dass die Rücklinie wirklich am Loop-Node endet.

• Schleife, die gar nicht nötig war? Wenn jeder Node ohnehin pro Item läuft, lös den Loop wieder auf. Er macht den Workflow nur komplizierter und langsamer.

Mini-Übung: zwei Antworten je nach Temperatur

Wir verzweigen den Wetter-Workflow: bei über 20 °C eine fröhliche, sonst eine kühle Nachricht.

  1. IF anhängen

    Hinter den Set-Node (mit Feld tempC aus Kapitel 9) einen IF setzen.

  2. Bedingung

    Wert {{ $json.tempC }} · Datentyp Number · Operation is greater than · 20.

  3. true-Zweig

    Vom oberen Ausgang einen Set-Node: Feld text = 🏖️ Heute warm: {{ $json.tempC }} °C!

  4. false-Zweig

    Vom unteren Ausgang einen Set-Node: Feld text = 🧥 Eher kühl: {{ $json.tempC }} °C.

  5. Testen

    Klicke unten am Canvas auf Execute workflow. Bis n8n 1.x hieß derselbe Knopf „Test workflow“. Beobachte, welcher Zweig sich pink einfärbt. Das ist der Weg, den dein Item genommen hat.

💡 Später wieder zusammenführen Wenn beide Zweige am Ende dasselbe tun (z. B. die Nachricht verschicken), häng einen Merge dahinter und führe sie zusammen. Dann brauchst du den Versand-Node nur einmal. Der Modus Append reicht dafür.

  • Welcher Merge-Modus hängt zwei Listen einfach hintereinander?
  • Du willst „für jedes der 50 Items eine E-Mail“. Brauchst du dafür einen Loop?
  • Woran erkennst du im Test, welchen Zweig ein Item genommen hat?
