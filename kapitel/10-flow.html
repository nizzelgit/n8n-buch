Flow-Logik: IF, Switch, Merge & Loops

Bisher liefen unsere Workflows schnurgerade von links nach rechts. Jetzt bringen wir Entscheidungen hinein: Je nach Daten geht es einen anderen Weg. Danach führen wir die getrennten Wege wieder zusammen. Und wir klären, wann du wirklich eine Schleife brauchst. Spoiler: viel seltener, als du denkst.

ca. 22 Minuten Niveau: Mittel Voraussetzung: Kapitel 5, 6 & 9

Was du mitbringen solltest

  • Das „läuft pro Item“-Prinzip (Kapitel 5). Es erklärt, warum du Schleifen selten brauchst.
  • Bedingungen aus Kapitel 6 (>, ||, …) und dem Filter (Kapitel 9).

IF: die Weiche mit zwei Ausgängen

Der IF-Node ist eine Weiche. Er prüft für jedes Item eine Bedingung, zum Beispiel „ist die Temperatur größer als 20?“. Je nach Antwort schickt er das Item in einen von zwei Ausgängen: true heißt „Bedingung erfüllt“, false heißt „nicht erfüllt“. Anders als der Filter aus Kapitel 9 wirft der IF-Node nichts weg. Beide Gruppen laufen weiter, nur eben in getrennten Zweigen. Im Node-Panel steht der Node übrigens als If, nicht in Großbuchstaben.

  1. IF anlegen & öffnen

    Klicke auf das Plus hinter deinem letzten Node und tippe im Suchfeld „If“ ein. Klicke auf den Treffer If. Der Node hängt jetzt am Workflow und öffnet sich. Du siehst den Bereich Conditions (englisch für „Bedingungen“). Er sieht genauso aus wie beim Filter aus Kapitel 9. Weitere Zeilen legst du bei Bedarf mit Add Condition an.

  2. Bedingung setzen

    Trage links den Wert {{ $json.tempC }} ein. Klicke dann auf das Dropdown in der Mitte. Wähle dort zuerst den Datentyp Number (Zahl) und dann die Operation is greater than („ist größer als“). Trage rechts 20 ein.

  3. Die zwei Ausgänge verbinden

    Schließe den Node. Auf dem Canvas hat der IF-Node jetzt zwei kleine Punkte an der rechten Seite. Der obere ist der true-Ausgang, der untere der false-Ausgang. Ziehe mit gedrückter Maustaste vom oberen Punkt eine Linie zum „warm“-Zweig und vom unteren zum „kühl“-Zweig. Fertig ist die Verzweigung.

Ein Stolperstein: Der IF-Node nimmt Datentypen genau. Kommt tempC als Text aus der API (also als "18" statt als Zahl 18), bricht der Node mit einer Fehlermeldung zum Typ ab. Die Meldung sieht dramatischer aus, als sie ist. Du hast zwei Auswege: Entweder du wandelst den Wert vorher in eine Zahl um (Kapitel 9), oder du schaltest im Node den Regler Convert types where required ein („Typen bei Bedarf umwandeln“). In der Doku steht dieselbe Einstellung stellenweise noch unter ihrem alten Namen Less Strict Type Validation.

Switch: die Weiche mit vielen Ausgängen

Brauchst du mehr als zwei Wege, nimm den Switch-Node. Hier legst du mit dem Knopf Add Routing Rule mehrere Routing Rules an, also Verteil-Regeln. Jede Regel bekommt ihren eigenen Ausgang. So sortierst du zum Beispiel nach Kategorie, Status oder Sprache. Die Ausgänge heißen zunächst nur „0“, „1“, „2“. Schaltest du in einer Regel Rename Output ein, trägt der Ausgang stattdessen den Namen, den du unter Output Name vergibst.

Switch-ModusSortiert nach …
Rulesfrei definierten Bedingungen: ein Ausgang pro Regel (wie mehrere IFs)
Expressioneinem Index, den du berechnest. Du setzt Number of Outputs und schreibst in Output Index eine Expression, die eine Zahl ab 0 zurückgibt (für Fortgeschrittene)
Switch = IF mit mehr Türen Denk an Switch als IF mit beliebig vielen Ausgängen. Zwei Wege → IF. Drei oder mehr → Switch. Für Items, die zu keiner Regel passen, gibt es einen Fallback-Ausgang (Auffang-Ausgang). Du holst ihn dir im Node über Options → Add option → Fallback Output → Extra Output. Wichtig: Lässt du die Einstellung auf None, verschwinden nicht passende Items lautlos, ganz ohne Fehlermeldung.

Merge: getrennte Zweige zusammenführen

Nach einer Verzweigung willst du die Wege oft später wieder zusammenführen. Das macht der Merge-Node (englisch „merge“ = verschmelzen). Er startet mit zwei Eingängen und einem Ausgang. Brauchst du mehr Eingänge, setzt du das Feld Number of Inputs höher. Das geht in jedem Modus außer Combine, denn Combine vergleicht immer genau zwei Listen.

Merge-ModusMacht
Appendhängt die Listen einfach hintereinander (erst Input 1, dann Input 2)
Combine → Combine By: Matching Fieldsverbindet Items, die in einem Feld übereinstimmen (z. B. gleiche id)
Combine → Combine By: Positionverbindet das 1. mit dem 1., das 2. mit dem 2. Item usw.
Combine → Combine By: All Possible Combinationspaart jedes Item aus Input 1 mit jedem aus Input 2 (Kreuzprodukt)
SQL Querydu schreibst den Join selbst; die Eingänge heißen in der Abfrage input1, input2 und so weiter
Choose Branchwartet auf beide Eingänge und reicht danach nur die Daten eines Eingangs unverändert weiter

Kleiner Suchtipp: Die drei Combine By-Varianten findest du im Node nicht direkt im Dropdown Mode. Stelle zuerst Mode auf Combine. Erst danach erscheint darunter das zweite Dropdown Combine By. Beim ersten Mal habe ich dort lange gesucht.

IF + Merge sind die Arbeitspferde Verzweigen mit IF, später mit Merge wieder zusammen: Dieses Paar deckt fast alle „mal so, mal so“-Abläufe ab. Switch nur, wenn es wirklich mehr als zwei Wege sind.

Loops: meistens brauchst du sie nicht

Ein Loop ist eine Schleife: derselbe Schritt wird mehrfach hintereinander ausgeführt. Der häufigste Anfänger-Reflex lautet: „Ich habe eine Liste, also brauche ich eine Schleife.“ Fast nie! Erinnere dich an Kapitel 5: Ein Node läuft automatisch pro Item. Hast du 100 Items, läuft der nächste Node 100-mal, ganz ohne Schleife.

Die Regel zuerst Willst du „für jede Zeile etwas tun“, sorg einfach dafür, dass jede Zeile ein Item ist (z. B. „Split Out“ aus Kapitel 9). Den Rest macht n8n durch Wiederholung pro Item von selbst.

Eine echte Schleife brauchst du nur in Sonderfällen. Der passende Node heißt im Node-Panel „Loop Over Items (Split in Batches)“. Auf dem Canvas trägt er danach den kurzen Namen „Loop Over Items“. Diese Sonderfälle gibt es:

  • Batching: Eine API erlaubt nur 10 Einträge pro Aufruf. Du setzt im Node das Feld Batch Size (Häppchengröße) auf 10 und arbeitest die Liste in Häppchen ab.
  • Rate-Limits / Pausen: Du willst zwischen den Durchläufen warten, etwa weil die API sonst blockt (Kapitel 23).
  • Zustand über Runden: Jeder Durchlauf baut auf dem Ergebnis des vorherigen auf.

Der Node hat zwei Ausgänge, und ihre Reihenfolge musst du dir merken: Am Node sitzt done („fertig“) oben und loop („Schleife“) darunter. An loop hängst du die Verarbeitung, an done alles, was erst nach der letzten Runde laufen soll. So ist es seit der dritten Version des Nodes, die im Herbst 2023 kam. Ältere Screenshots und Videos zeigen die umgekehrte Belegung, und genau daher kommt die Verwechslung. Woran du den Fehler erkennst: Dein Verarbeitungsschritt läuft gar nicht oder nur ein einziges Mal ganz am Ende. Dann hängt er am falschen Ausgang.

Wenn etwas schiefgeht

• Schleife bleibt nach dem ersten Batch stehen? Der verarbeitende Zweig muss zurück zum Loop-Node führen, sonst wird nicht weitergezählt. Prüfe, dass die Rücklinie wirklich am Loop-Node endet.

• Schleife, die gar nicht nötig war? Wenn jeder Node ohnehin pro Item läuft, lös den Loop wieder auf. Er macht den Workflow nur komplizierter und langsamer.

Mini-Übung: zwei Antworten je nach Temperatur

Wir verzweigen jetzt den Wetter-Workflow aus Kapitel 9: Bei über 20 °C soll eine fröhliche Nachricht entstehen, sonst eine kühle.

  1. IF anhängen

    Öffne den Wetter-Workflow. Klicke auf das Plus hinter dem Set-Node (der mit dem Feld tempC aus Kapitel 9), suche nach „If“ und wähle den If-Node aus.

  2. Bedingung

    Trage im geöffneten Node ein: links den Wert {{ $json.tempC }}, in der Mitte den Datentyp Number und die Operation is greater than, rechts 20. Schließe den Node.

  3. true-Zweig

    Ziehe vom oberen Ausgang eine Verbindung zu einem neuen Set-Node. Lege darin ein Feld text an mit dem Wert Heute warm: {{ $json.tempC }} °C!

  4. false-Zweig

    Ziehe vom unteren Ausgang eine Verbindung zu einem zweiten Set-Node. Feld text, Wert Eher kühl: {{ $json.tempC }} °C.

  5. Testen

    Klicke unten am Canvas auf Execute workflow (führt den ganzen Workflow einmal aus; bis n8n 1.x hieß derselbe Knopf „Test workflow“). Beobachte, welcher Zweig sich pink einfärbt. Das ist der Weg, den dein Item genommen hat. Der andere Zweig bleibt grau, und sein Set-Node zeigt keine Daten. Das ist richtig so.

Später wieder zusammenführen Wenn beide Zweige am Ende dasselbe tun (z. B. die Nachricht verschicken), häng einen Merge dahinter und führe sie zusammen. Dann brauchst du den Versand-Node nur einmal. Der Modus Append reicht dafür.
