Expressions & der Ausdruckseditor

In Kapitel 5 hast du {{ $json.feld }} zum ersten Mal benutzt. Jetzt machen wir daraus echtes Können: Texte bauen, mit Datum rechnen, Bedingungen prüfen, fehlende Werte abfangen. Das ist der Werkzeugkasten, mit dem du Daten in jede gewünschte Form bringst — und der Ausdruckseditor ist die Werkbank.

⏱ ca. 20 Minuten 🎯 Niveau: Einstieg → Mittel 🧩 Voraussetzung: Kapitel 5 (Items & Datenfluss)

📋 Was du können solltest

  • Du weißt, dass zwischen Nodes Items fließen und jedes Item ein json-Fach hat (Kap. 5).
  • Du hast schon einmal ein Feld auf Expression umgeschaltet und {{ $json.… }} getippt (Kap. 4).
  • Zum Mitmachen: irgendein Workflow mit ein, zwei Nodes, die Daten liefern — z. B. der Wetter-Workflow aus Kapitel 4.

Was eine Expression wirklich ist

Eine Expression ist ein kleines Stück Code, das n8n beim Ausführen durch einen echten Wert ersetzt. Erkennungszeichen sind die doppelten geschweiften Klammern {{ }}. Und hier ist das ganze Geheimnis in einem Satz:

⚡ Die eine Regel, die alles erklärt Alles innerhalb von {{ }} ist Code (kleines JavaScript), das n8n berechnet. Alles außerhalb ist ganz normaler Text, der so bleibt, wie er ist. Du kannst beides beliebig mischen.

Schau dir dieses Mischbeispiel an. Der normale Text bleibt stehen, nur die beiden Klammer-Stellen werden ersetzt:

  Eine Expression aus Text + zwei berechneten Stellen
Hallo {{ $json.name }}, heute sind es {{ $json.temp }} °C.
// wird zu:  Hallo Anna, heute sind es 17.4 °C.

„Code“ klingt nach viel — ist es aber nicht. In 95 % der Fälle schreibst du nur einen Feldnamen ($json.temp), hängst vielleicht eine Funktion an (.toUpperCase()) oder rechnest ein bisschen (+ 1). Mehr brauchst du am Anfang nicht.

Fest oder Expression? Der Umschalter an jedem Feld

Fast jedes Eingabefeld in n8n hat zwei Betriebsarten. Über dem Feld (oder beim Daraufzeigen) erscheinen zwei kleine Reiter:

  • Fest (engl. Fixed): Was du tippst, gilt wörtlich. Tippst du {{ $json.name }}, steht später buchstäblich „{{ $json.name }}“ drin — die Klammern werden nicht ausgewertet.
  • Expression: Das Feld wird ausgewertet. Es bekommt einen leicht bläulichen Hintergrund und eine Monospace-Schrift — dein optisches Signal „hier rechnet n8n“.
1 ins Feld zeigen → 2 Reiter Expression klicken → 3 Feld wird bläulich → 4 {{ … }} eingeben
Wenn etwas schiefgeht Die {{ }} erscheinen wörtlich im Ergebnis? Dann steht das Feld noch auf Fest. Klick oben auf Expression — der bläuliche Hintergrund bestätigt, dass es umgeschaltet ist.

Der Ausdruckseditor — deine Werkbank

Sobald du in ein Expression-Feld klickst, klappt der Ausdruckseditor auf. Er ist zweigeteilt: oben tippst du die Expression, darunter zeigt n8n sofort das Ergebnis — live, mit den echten Daten, die gerade hereinkommen. So musst du nie raten, ob deine Expression stimmt.

  1. In das Expression-Feld klicken

    Klicke in das (bläuliche) Feld. Direkt darunter erscheint ein zweiter Bereich mit der Überschrift „Result“ bzw. „Ergebnis“.

  2. Tippen und live mitlesen

    Während du tippst, aktualisiert n8n das Ergebnis bei jedem Zeichen. Steht unten der erwartete Wert in Grün — passt alles. Steht dort rot ein Fehler, siehst du sofort, dass etwas nicht stimmt.

  3. Was du jetzt siehst

    Oben dein Ausdruck (farbig hervorgehoben: Klammern, Variablen, Funktionen), unten das fertig berechnete Resultat. Genau dieses Live-Ergebnis ist dein Sicherheitsnetz.

Zwei Komfort-Funktionen ersparen dir fast alles Abtippen:

  1. Felder per Drag-and-drop einsetzen

    Im Eingangspanel links (Reiter Schema) siehst du alle ankommenden Felder. Zieh ein Feld mit der Maus direkt in den Editor — n8n fügt die fertige Expression wie {{ $json.current.temperature_2m }} automatisch ein. Kein Tippfehler möglich.

  2. Autovervollständigung nutzen

    Tippst du $json. (mit Punkt), öffnet sich eine Liste aller verfügbaren Felder und der passenden Funktionen. Mit ↓/↑ auswählen, Enter übernehmen.

⚡ Das Live-Ergebnis ist dein bester Freund Bau Expressions schrittweise und beobachte unten das Resultat. Erst {{ $json.name }} → stimmt? Dann .toUpperCase() anhängen → stimmt? So findest du Fehler sofort, statt erst beim Ausführen des ganzen Workflows.

Die wichtigsten Variablen auf einen Blick

Innerhalb von {{ }} stehen dir besondere Variablen zur Verfügung — alle beginnen mit einem $. Das sind die, die du immer wieder brauchst:

VariableWas sie liefert
$jsonDie Daten des aktuellen Items aus dem vorherigen Node. Dein Brot-und-Butter-Zugriff.
$json.feldEin bestimmtes Feld daraus (mit Punkten in die Tiefe: $json.current.temp).
$('Node-Name')Zugriff auf einen beliebigen früheren Node, z. B. $('Webhook').item.json.email.
$nowAktuelles Datum + Uhrzeit (als rechenbares Datum-Objekt, siehe unten).
$todayHeute um 00:00 Uhr — praktisch für „seit heute Morgen“.
$itemIndexDie Position des aktuellen Items in der Liste (0, 1, 2 …).
$workflow.nameName des laufenden Workflows. Auch da: $workflow.id.
$varsSelbst angelegte Umgebungs-Variablen (z. B. ein API-Basis-Pfad). Mehr in Kapitel 24.
⚡ Diese drei reichen für den Anfang $json (Daten von nebenan), $('Node') (Daten von irgendwo früher) und $now (Datum/Zeit). Mit diesen dreien verdrahtest du gefühlt jeden Workflow. Den Rest schlägt dir die Autovervollständigung vor.

Text zusammenbauen & umformen

Der häufigste Job für Expressions: aus rohen Daten einen schönen Satz machen. Text klebst du einfach mit + zusammen, oder — viel bequemer — du mischst Text und {{ }} direkt, wie in Abb. 6.1. Auf jeden Text kannst du Funktionen anwenden, indem du sie mit einem Punkt anhängst:

FunktionmachtBeispiel → Ergebnis
.toUpperCase()GROSSBUCHSTABEN"anna".toUpperCase() → „ANNA“
.toLowerCase()kleinbuchstaben"ANNA".toLowerCase() → „anna“
.trim()Leerzeichen am Rand weg" hi ".trim() → „hi“
.replace(a, b)ersetzt a durch b"a-b".replace("-", " ") → „a b“
.split(t)zerteilt in eine Liste"a,b,c".split(",") → [a, b, c]
.slice(0, 3)schneidet einen Teil aus"Hallo".slice(0, 3) → „Hal“
.lengthAnzahl Zeichen (ohne Klammern!)"Anna".length → 4
n8n-Komfortfunktionen — über die Standardfunktionen hinaus n8n ergänzt eigene, praktische Funktionen, die in der Autovervollständigung auftauchen, etwa .toTitleCase() („anna meier“ → „Anna Meier“), .isEmpty() (prüft auf leer) oder .extractEmail(). Du musst sie nicht kennen — tipp einfach den Punkt und stöbere durch die Vorschläge.

Mit Datum & Uhrzeit rechnen

Datumsrechnen ist berüchtigt — in n8n ist es angenehm. $now und $today sind keine simplen Texte, sondern rechenbare Datums-Objekte (n8n nutzt dafür die Bibliothek Luxon). Damit kannst du formatieren, addieren und Abstände berechnen.

Formatieren mit .toFormat()

Ein rohes Datum sieht so aus: 2026-05-29T10:00:00.000+02:00 — unschön für Menschen. Mit .toFormat('…') bringst du es in jede Form. Die wichtigsten Bausteine:

BausteinBedeutungBeispiel
ddTag, zweistellig29
MMMonat, zweistellig05
yyyyJahr, vierstellig2026
HHStunde (24h)10
mmMinute00
ccccWochentag ausgeschriebenFriday
MMMMMonat ausgeschriebenMay

Addieren, subtrahieren, Abstände

SchreibweiseErgebnis
{{ $now.plus({ days: 7 }) }}Datum in einer Woche
{{ $now.minus({ hours: 2 }) }}vor zwei Stunden
{{ $now.toFormat('HH:mm') }}nur die Uhrzeit, z. B. „10:00“
{{ $now.diff($today, 'hours').hours }}vergangene Stunden seit Mitternacht
{{ $now.toFormat('cccc') }}Wochentag „Friday“ (für Deutsch: $now.setLocale('de').toFormat('cccc'))
Wenn etwas schiefgeht Ein Datum aus deinen Daten (z. B. $json.datum) lässt sich nicht formatieren? Solche Felder kommen oft als reiner Text an, nicht als Datums-Objekt. Wandle sie zuerst um: {{ $json.datum.toDateTime().toFormat('dd.MM.yyyy') }}. $now/$today sind dagegen schon Datums-Objekte — die brauchen das nicht.

Zahlen & Rechnen

Innerhalb von {{ }} rechnest du ganz normal: + - * / und Klammern. Zwei Funktionen brauchst du oft, um Zahlen hübsch zu machen:

SchreibweiseErgebnis
{{ $json.preis * 1.19 }}Preis inkl. 19 % (einfaches Rechnen)
{{ (17.456).toFixed(1) }}auf 1 Nachkommastelle: „17.5“
{{ Math.round($json.temp) }}kaufmännisch runden: 17.4 → 17
{{ Number($json.menge) + 1 }}Text „5“ erst in Zahl wandeln, dann rechnen → 6
Wenn etwas schiefgeht Statt zu rechnen, werden Zahlen aneinandergehängt? "5" + 1 ergibt „51“, nicht 6 — weil die „5“ als Text ankam. Pack solche Werte in Number(…), dann rechnet n8n richtig. Im Schema (Kap. 5) erkennst du am Typ string vs. number, ob ein Wert Text oder Zahl ist.

Bedingungen & Standardwerte

Oft soll der Wert davon abhängen, was in den Daten steht. Dafür gibt es den ternären Operator Bedingung ? A : B — sprich „wenn Bedingung, dann A, sonst B“:

  Wenn … dann … sonst …
{{ $json.temp > 20 ? 'warm 🌞' : 'kühl 🧥' }}
// temp = 17.4  →  Ergebnis: "kühl 🧥"

Ein häufiger Stolperstein: ein Feld fehlt mal oder ist leer. Dann willst du einen Standardwert statt eines leeren Ergebnisses. Dafür gibt es zwei kurze Schreibweisen:

SchreibweiseBedeutung
{{ $json.name ?? 'Unbekannt' }}Nimm name; fehlt es, nimm „Unbekannt“.
{{ $json.name || 'Unbekannt' }}Ähnlich, springt auch bei leerem Text „“ ein.
{{ $json.adresse?.stadt }}Sicherer Zugriff: kein Fehler, falls adresse fehlt.
{{ $if($json.temp > 20, 'warm', 'kühl') }}n8n-Kurzform fürs ternäre Wenn-Dann.
⚡ ?? rettet dich vor leeren Ergebnissen Immer wenn ein Feld manchmal fehlen könnte (z. B. ein optionales Formularfeld), häng ?? 'Standard' an. So steht nie ein leerer oder kaputter Wert in deiner Nachricht — sondern ein sauberer Ersatz.

Listen verarbeiten

Manchmal steckt in einem Feld eine ganze Liste (ein Array, z. B. mehrere Tags). Damit kannst du auch umgehen:

SchreibweiseErgebnis
{{ $json.tags.length }}Anzahl der Einträge in der Liste
{{ $json.tags[0] }}der erste Eintrag (Zählung beginnt bei 0!)
{{ $json.tags.join(', ') }}alle Einträge zu einem Text: „news, eilig, top“
{{ $json.tags.first() }}n8n-Komfort: der erste (auch .last())
Der Unterschied: Liste in einem Feld vs. viele Items Verwechsle das nicht mit dem „läuft pro Item“-Prinzip aus Kapitel 5. $json.tags ist eine Liste innerhalb eines Items — die verarbeitest du mit Expressions wie oben. Mehrere Items dagegen bearbeitet n8n automatisch nacheinander. Zwei verschiedene Ebenen.

Mini-Spickzettel

Die Schreibweisen, die du am häufigsten brauchst — zum schnellen Nachschlagen (die vollständige Sammlung folgt in Anhang C):

  Die Top-Expressions auf einen Blick
// Felder
{{ $json.feld }}                       // Feld vom vorherigen Node
{{ $('Node').item.json.feld }}      // Feld von irgendwo früher

// Text
{{ $json.name.toUpperCase() }}        // GROSS
{{ $json.a + ' ' + $json.b }}      // zusammenkleben

// Datum
{{ $now.toFormat('dd.MM.yyyy') }}   // 29.05.2026
{{ $now.plus({ days: 7 }) }}       // in einer Woche

// Bedingung & Fallback
{{ $json.temp > 20 ? 'warm' : 'kühl' }}
{{ $json.name ?? 'Unbekannt' }}       // Standardwert

✅ Selbsttest — sitzt der Werkzeugkasten?

  • Was ist der Unterschied zwischen dem Reiter Fest und Expression?
  • Wo siehst du sofort, ob deine Expression das Richtige ergibt?
  • Wie machst du aus $now die Anzeige „29.05.2026“?
  • Ein Feld spitzname fehlt manchmal. Wie sorgst du für den Ersatz „Gast“?
  • Warum ergibt {{ "5" + 1 }} nicht 6 — und wie behebst du es?
Antworten 1) Fest = wörtlich, Expression = wird berechnet (bläuliches Feld). · 2) Im Live-Ergebnis unter dem Ausdruck. · 3) {{ $now.toFormat('dd.MM.yyyy') }}. · 4) {{ $json.spitzname ?? 'Gast' }}. · 5) Die „5“ ist Text → wird angehängt; mit {{ Number("5") + 1 }} wird richtig gerechnet.

Damit hast du den Werkzeugkasten beisammen, um Daten in jede Form zu bringen.
