Kernkonzepte: Nodes, Items & Datenfluss

Wenn ein einziges Kapitel dieses Buchs darüber entscheidet, ob du n8n wirklich verstehst, dann dieses. Hier klären wir, was genau zwischen den Nodes hin- und herfließt — und wie du darauf zugreifst.

⏱ ca. 24 Minuten 🎯 Niveau: Einstieg → Mittel ⚡ Das Herzstück des Buchs

Die eine Sache, die alles erklärt: das Item

Zwischen zwei Nodes fließen keine „Texte“ oder „Zahlen“, sondern Items. Ein Item ist ein kleines Datenpaket. Und ganz wichtig:

⚡ Die goldene Regel Ein Node bekommt immer eine Liste von Items herein und gibt eine Liste von Items heraus. Auch wenn es nur ein einziges Item ist, ist es technisch eine Liste mit einem Eintrag. Verinnerliche das, und n8n wird durchschaubar.

Jedes Item hat zwei Fächer:

  • json – die eigentlichen Daten als JSON-Objekt (Felder mit Werten). 95 % der Zeit arbeitest du hiermit.
  • binary – optionale Dateianhänge (Bild, PDF, …). Brauchst du erst bei Datei-Workflows.

Wie Items in der Oberfläche aussehen

n8n zeigt dieselben Items in drei Ansichten an — du wählst sie über die Reiter Tabelle / JSON / Schema im Eingangs- und Ausgangspanel. Es ist immer dasselbe darunter, nur anders dargestellt:

⚡ Tabelle zum Überblicken, JSON zum Verstehen, Schema zum Verdrahten Die Schema-Ansicht ist beim Bauen am wertvollsten: Du siehst alle verfügbaren Feldnamen — und kannst sie per Drag-and-drop direkt in ein Expression-Feld ziehen, statt sie abzutippen.

JSON in 3 Minuten (für alle, die unsicher sind)

JSON ist nur eine Schreibweise für strukturierte Daten. Du musst es nicht schreiben können, aber lesen schon. Es gibt genau diese Bausteine:

  Die JSON-Bausteine
{
  "text":    "in Anführungszeichen",   // String (Text)
  "zahl":    42,                  // Number
  "wahr":    true,                // Boolean (true/false)
  "leer":    null,                // nichts
  "liste":   [1, 2, 3],           // Array (geordnete Liste)
  "objekt":  {                       // verschachteltes Objekt
    "stadt": "Berlin"
  }
}

Das Wichtigste ist Verschachtelung: Objekte können in Objekten stecken. Um an Berlin heranzukommen, schreibst du den Pfad mit Punkten: objekt.stadt. Genau das machst du in Expressions ständig.

Der Zugriff: Expressions & $json

Eine Expression ist ein kleines Stück Code in doppelten geschweiften Klammern, das n8n beim Ausführen durch den echten Wert ersetzt. Die wichtigste Variable darin ist $json:

ExpressionBedeutung / Ergebnis
{{ $json.name }}Das Feld name des aktuellen Items → „Anna“
{{ $json.current.temperature_2m }}Verschachtelt: in current das Feld temperature_2m
{{ $json.liste[0] }}Das erste Element einer Liste (Zählung beginnt bei 0!)
{{ $json.alter + 1 }}Rechnen geht auch → 30
{{ $json.name.toUpperCase() }}Funktionen anwenden → „ANNA“
{{ $now }}Aktuelles Datum/Uhrzeit
Woher weiß ich die Feldnamen? Aus dem Eingangspanel des Nodes (Schema-Ansicht). n8n zeigt dir dort genau die Felder, die gerade ankommen. Du musst nichts raten — und kannst Felder per Drag-and-drop ins Feld ziehen.

Auf andere Nodes zugreifen: $('Node-Name')

$json bezieht sich immer auf den direkt vorherigen Node. Manchmal brauchst du aber einen Wert aus einem weiter zurückliegenden Node — etwa die ursprüngliche E-Mail aus dem Trigger, nachdem schon drei Nodes dazwischenliegen. Dafür gibt es:

  Zugriff auf einen benannten Node
// Hol das Feld "email" aus dem Node namens "Webhook"
{{ $('Webhook').item.json.email }}
⚡ Die zwei Zugriffe, die du wirklich brauchst

$json.feld → Wert aus dem vorherigen Node.

$('Name').item.json.feld → Wert aus einem beliebigen früheren Node.

Mit diesen beiden verdrahtest du gefühlt jeden Workflow.

Ein Item oder viele? Das „läuft pro Item“-Prinzip

Hier passiert der häufigste Aha-Moment. Bekommt ein Node mehrere Items, führt er seine Aktion für jedes Item einzeln aus. Drei Items rein → Aktion läuft dreimal → drei Items raus.

⚡ Warum das so genial ist Du musst keine Schleife programmieren. Willst du „für jede Zeile in der Tabelle eine Nachricht“, sorgst du einfach dafür, dass jede Zeile ein Item ist — den Rest erledigt n8n automatisch durch Wiederholung pro Item.

Daten „festpinnen“ zum Testen (Pinning)

Beim Entwickeln willst du nicht bei jedem Test echte E-Mails verschicken oder eine API hundertmal aufrufen. Lösung: Pin Data. Du führst einen Node einmal aus und „pinnst“ sein Ergebnis fest — bei den nächsten Tests benutzt n8n diese gespeicherten Daten, statt neu abzurufen. Ein angepinnter Node bekommt ein 📌-Symbol.

1 Node ausführen → 2 im Ausgangspanel auf 📌 „Pin“ klicken → 3 ab jetzt fixe Testdaten

Wie das alles zusammenspielt — ein Durchlauf

Fügen wir das Wissen zusammen. So „denkt“ n8n, wenn du auf Test klickst:

  1. Trigger erzeugt das/die Start-Item(s)

    Beim manuellen Trigger ist das ein leeres Item, bei „Sheets lesen“ z. B. eine Zeile pro Item.

  2. Items wandern in den nächsten Node

    Der nimmt sie als Eingang (linkes Panel).

  3. Der Node arbeitet — pro Item

    Er wendet seine Einstellungen an; Expressions werden jetzt zu echten Werten ausgewertet.

  4. Er gibt neue Items aus

    Diese erscheinen im Ausgang (rechtes Panel) und sind der Eingang des nächsten Nodes.

  5. … und so weiter bis zum Ende

    Bis kein Node mehr folgt. Jeder Schritt ist in den Ausführungen nachvollziehbar.

✅ Selbsttest — verstehst du den Kern?

  • Was ist der Unterschied zwischen $json und $('Trigger').item.json?
  • Du hast 5 Items im Eingang eines „Slack senden“-Nodes. Wie viele Nachrichten gehen raus?
  • Welche Ansicht (Tabelle/JSON/Schema) nutzt du, um schnell alle Feldnamen zu sehen?
  • Wozu pinnst du Daten?
Antworten 1) $json = vorheriger Node, $('Trigger')… = ein bestimmter, beliebiger Node. · 2) Fünf — der Node läuft pro Item. · 3) Schema. · 4) Um beim Testen keine echten Aktionen auszulösen und APIs zu schonen.

Damit hast du das mentale Modell, auf dem alles andere aufbaut. Im nächsten Kapitel machen wir Expressions zur echten Stärke: Datumsrechnen, Texte bauen, Bedingungen, kleine Tricks — der Werkzeugkasten, mit dem du Daten in jede gewünschte Form bringst.
