Der HTTP-Request-Node: jede API ansprechen

Es gibt zwar fertige Nodes für hunderte Dienste — aber der HTTP-Request-Node ist der Generalschlüssel: Mit ihm sprichst du jeden Webdienst an, der eine Schnittstelle (API) hat, auch wenn es keinen eigenen Node dafür gibt. Verstehst du diesen einen Node, steht dir das halbe Internet offen.

⏱ ca. 22 Minuten 🎯 Niveau: Mittel 🧩 Voraussetzung: Kapitel 4 & 5

📋 Was du mitbringen solltest

  • Du hast in Kapitel 4 schon einen einfachen GET-Request gebaut (Wetter holen).
  • JSON lesen und Pfade wie $json.current.temperature_2m (Kapitel 5) sind dir vertraut.
  • Für die Übung brauchst du keinen Account — wir nutzen einen offenen Echo-Dienst.

Was bei einem HTTP-Request passiert

Ein HTTP-Request ist wie ein adressierter Brief an einen Server. Er besteht immer aus denselben Teilen — und genau die füllst du im Node aus:

TeilWofür
MethodDie Absicht: holen, senden, ändern, löschen (siehe Tabelle unten).
URLDie Adresse des Dienstes — wohin der Brief geht.
Query-ParameterZusätze an der URL nach dem ?, z. B. ?stadt=Berlin.
HeadersMetadaten, z. B. „ich erwarte JSON" oder ein Zugangsschlüssel.
BodyDer eigentliche Inhalt — nur beim Senden (POST/PUT), meist als JSON.
AuthenticationWer du bist — falls der Dienst einen Login verlangt (Kapitel 12).

Die vier Methoden, die du brauchst

MethodBedeutungBeispiel
GETDaten holen (ändert nichts)Wetter abrufen, Liste lesen
POSTEtwas neu anlegen / sendenNachricht senden, Datensatz erstellen
PUT / PATCHEtwas ändern (ganz / teilweise)Kontakt aktualisieren
DELETEEtwas löschenEintrag entfernen
⚡ 80 % ist GET und POST Daten lesen = GET, Daten schicken = POST. Mit diesen beiden baust du die allermeisten Integrationen. PUT/PATCH/DELETE brauchst du erst, wenn du fremde Datensätze gezielt pflegst.

Der Node im Detail

Öffne einen frischen HTTP-Request-Node (Doppelklick). Oben stehen Method und URL, darunter die Authentication und dann drei Schalter, die je einen Bereich aufklappen: Send Query Parameters, Send Headers und Send Body.

Query-Parameter sauber setzen

In Kapitel 4 haben wir die Parameter direkt in die URL geschrieben (…/forecast?latitude=52.52&longitude=13.41). Das geht — aber es gibt einen aufgeräumteren Weg: Schalte „Send Query Parameters" ein und trag jeden Parameter als Name/Wert-Paar ein. Vorteil: übersichtlich, und jeder Wert kann eine Expression sein.

💡 Import cURL — der größte Zeitsparer Viele API-Dokus zeigen Beispiele als curl-Befehl. Klick oben im Node auf „Import cURL", füge den Befehl ein — und n8n füllt Method, URL, Header und Body automatisch aus. Danach nur noch anpassen, fertig.

Daten senden: der Body bei POST

Beim POST schickst du Inhalt mit. Stell Method auf POST, schalte „Send Body" ein und wähle als Body Content Type meist JSON. Dann gibst du den Body als JSON ein — und darfst überall Expressions verwenden:

  Body (JSON) — mit eingebetteter Expression
{
  "stadt": "Berlin",
  "temperatur": {{ $json.current.temperature_2m }},
  "gemeldet_am": "{{ $now.toFormat('dd.MM.yyyy HH:mm') }}"
}
Wenn etwas schiefgeht — Zahl vs. Text im Body Eine Zahl steht ohne Anführungszeichen ("temperatur": {{ … }}), ein Text mit ("gemeldet_am": "{{ … }}"). Vergisst du die Quotes bei Text, wird das JSON ungültig — die Vorschau zeigt dann einen roten Fehler.

Die Antwort lesen

Nach „▶ Schritt ausführen" steht die Antwort im Ausgang — meist als ein Item mit JSON. Zwei nützliche Optionen findest du ganz unten unter „Options":

  • Response → Response Format: Autodetect reicht fast immer; für Dateien (PDF/Bild) wählst du File.
  • Split Into Items: Liefert die API eine Liste, kannst du sie hier in ein Item pro Eintrag aufteilen — dann läuft der nächste Node automatisch pro Eintrag (Kapitel 5).
Authentication — kurz angerissen Verlangt ein Dienst Login, stell Authentication nicht auf „None". Kennt n8n den Dienst, wähle „Predefined Credential Type" und such ihn aus. Sonst „Generic Credential Type" → Header Auth (z. B. Header Authorization mit Wert Bearer DEIN_TOKEN). Niemals den Token offen in die URL schreiben. Wie Credentials sicher gespeichert werden, ist Thema von Kapitel 12.

Mini-Übung: einen POST senden und die Antwort lesen

Wir schicken Daten an einen offenen Echo-Dienst (er spiegelt einfach zurück, was er bekommt) — ideal zum Üben, ganz ohne Account. So siehst du genau, was du gesendet hast.

  1. Einen HTTP-Node anlegen

    Häng an einen manuellen Trigger einen HTTP Request und öffne ihn.

  2. Method auf POST stellen

    Feld Method → POST.

  3. Die URL eintragen

    Ins URL-Feld: https://postman-echo.com/post

  4. Body einschalten

    Send Body an, Body Content Type = JSON, Specify Body = Using JSON.

  5. Den Body eintippen

    Trag dieses JSON ein (gern mit Expression beim Zeitstempel):

  Body (JSON)
{
  "gruss": "Hallo aus n8n",
  "zeit": "{{ $now.toFormat('dd.MM.yyyy HH:mm') }}"
}

  1. Ausführen

    „▶ Schritt ausführen" klicken. Rechts erscheint die Antwort.

  2. Die Spiegelung finden

    Such im Ergebnis das Feld data — der Echo-Dienst gibt dort exakt deinen Body zurück. Damit ist bewiesen, dass dein POST samt JSON sauber angekommen ist.

Wenn etwas schiefgeht

• Roter Fehler „JSON parameter needs to be valid JSON"? Im Body fehlt ein Komma, eine Klammer oder Anführungszeichen. Die Vorschau zeigt dir die Stelle.

• Code 405 (Method Not Allowed)? Du sendest GET an eine Adresse, die POST erwartet (oder umgekehrt). Method anpassen.

✅ Selbsttest

  • Welche Method nimmst du zum Lesen, welche zum Senden?
  • Was ist der Vorteil der „Send Query Parameters"-Liste gegenüber Parametern direkt in der URL?
  • Wie schaltest du eine API-Liste in „ein Item pro Eintrag" um?
  • Was bedeutet ein Antwortcode 401 — und woran liegt es meist?
  • Wofür ist „Import cURL" gut?
Antworten 1) GET zum Lesen, POST zum Senden. · 2) Übersichtlich, und jeder Wert kann eine Expression sein; n8n baut die URL korrekt zusammen. · 3) Unter „Options" → Split Into Items. · 4) Nicht angemeldet/keine Berechtigung — meist fehlt oder stimmt das Auth-Token nicht. · 5) Einen curl-Befehl aus einer API-Doku einfügen, n8n füllt den Node automatisch aus.
