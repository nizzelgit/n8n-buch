Der HTTP-Request-Node: jede API ansprechen

Für hunderte Dienste gibt es fertige Nodes. Für alle anderen gibt es den HTTP-Request-Node: Mit ihm sprichst du jeden Webdienst an, der eine Schnittstelle (API) hat, auch wenn es keinen eigenen Node dafür gibt. Verstehst du diesen einen Node, kommst du an fast jede Web-API heran.

ca. 22 Minuten Niveau: Mittel Voraussetzung: Kapitel 4 & 5

Was du mitbringen solltest

  • Du hast in Kapitel 4 schon einen einfachen GET-Request gebaut (Wetter holen).
  • JSON lesen und Pfade wie $json.current.temperature_2m (Kapitel 5) sind dir vertraut.
  • Für die Übung brauchst du keinen Account. Wir nutzen einen offenen Echo-Dienst.

Was bei einem HTTP-Request passiert

Ein HTTP-Request ist wie ein adressierter Brief an einen Server. Er besteht immer aus denselben Teilen, und genau die füllst du im Node aus:

TeilWofür
MethodDie Absicht: holen, senden, ändern, löschen (siehe Tabelle unten).
URLDie Adresse des Dienstes: wohin der Brief geht.
Query-ParameterZusätze an der URL nach dem ?, z. B. ?stadt=Berlin.
HeadersMetadaten, z. B. „ich erwarte JSON“ oder ein Zugangsschlüssel.
BodyDer eigentliche Inhalt, nur beim Senden (POST/PUT), meist als JSON.
AuthenticationWer du bist, falls der Dienst einen Login verlangt (Kapitel 12).

Die vier Methoden, die du brauchst

MethodBedeutungBeispiel
GETDaten holen (ändert nichts)Wetter abrufen, Liste lesen
POSTEtwas neu anlegen / sendenNachricht senden, Datensatz erstellen
PUT / PATCHEtwas ändern (ganz / teilweise)Kontakt aktualisieren
DELETEEtwas löschenEintrag entfernen
80 % ist GET und POST Daten lesen = GET, Daten schicken = POST. Mit diesen beiden baust du die allermeisten Integrationen. PUT/PATCH/DELETE brauchst du erst, wenn du fremde Datensätze gezielt pflegst.

Der Node im Detail

Öffne einen frischen HTTP-Request-Node (Doppelklick). Ganz oben rechts im Parameter-Bereich sitzt der Knopf Import cURL. Darunter stehen Method und URL, dann die Authentication und dann drei Schalter, die je einen Bereich aufklappen: Send Query Parameters, Send Headers und Send Body. Am Fuß der Liste steht Add option. Damit holst du dir die Zusatzoptionen, um die es weiter unten geht.

Query-Parameter sauber setzen

In Kapitel 4 haben wir die Parameter direkt in die URL geschrieben (…/forecast?latitude=52.52&longitude=13.41). Das funktioniert. Aufgeräumter geht es so: Schalte Send Query Parameters ein. Darunter erscheint das Feld Specify Query Parameters, dort bleibt Using Fields Below stehen. Jetzt trägst du jeden Parameter als Name/Wert-Paar ein; weitere Zeilen holst du dir über Add Query Parameter. Das bleibt übersichtlich, und jeder Wert kann eine Expression sein.

Import cURL: der größte Zeitsparer Viele API-Dokus zeigen ihre Beispiele als curl-Befehl. Klick oben rechts im Node auf Import cURL. Es öffnet sich das Fenster Import cURL command mit dem Feld cURL Command. Befehl hineinkopieren, auf Import klicken, fertig: n8n füllt Method, URL, Query-Parameter, Header und Body aus. Lies den Hinweis im Fenster mit. Der Import überschreibt alles, was du im Node vorher eingestellt hast.

Daten senden: der Body bei POST

Beim POST schickst du Inhalt mit. Stell Method auf POST, schalte Send Body ein und wähle als Body Content Type den Eintrag JSON. Darunter erscheint Specify Body; stell es auf Using JSON. Jetzt tippst du den Body in das Feld darunter. Expressions sind darin überall erlaubt:

  Body (JSON) mit eingebetteter Expression
{
  "stadt": "Berlin",
  "temperatur": {{ $json.current.temperature_2m }},
  "gemeldet_am": "{{ $now.toFormat('dd.MM.yyyy HH:mm') }}"
}
Wenn etwas schiefgeht: Zahl oder Text im Body Eine Zahl steht ohne Anführungszeichen ("temperatur": {{ … }}), ein Text steht mit ("gemeldet_am": "{{ … }}"). Vergisst du die Quotes beim Text, wird das JSON ungültig. Die Vorschau zeigt dann einen roten Fehler.

Die Antwort lesen

Nach „▶ Schritt ausführen“ steht die Antwort im Ausgang, meist als ein Item mit JSON. Wie n8n sie behandelt, stellst du ganz unten im Node ein: Klick auf Add option und wähle Response. Der Eintrag klappt drei Felder auf:

  • Response Format: Autodetect reicht fast immer. Für Dateien (PDF, Bild) nimmst du File, für Antworten, die kein sauberes JSON sind, Text. JSON erzwingt die JSON-Auswertung, auch wenn der Server einen anderen Content-Type meldet. Bei File und Text kommt das Feld Put Output in Field dazu; es steht auf data.
  • Include Response Headers and Status: legt neben dem Body auch Statuscode und Header ins Item. Praktisch, wenn du den Code später auswerten willst.
  • Never Error: der Node bricht auch bei 404 oder 500 nicht ab, sondern reicht die Antwort weiter. Nimm das nur, wenn du den Statuscode danach wirklich selbst prüfst.

Eines suchst du hier vergeblich: ein Feld, das eine Liste in einzelne Items zerlegt. Das hat der Node nicht mehr. In n8n 1.x hieß die Option Split Into Items; heute steckt sie nur noch in den alten Node-Versionen 1 und 2. Neue HTTP-Request-Nodes legt n8n als Version 4.x an. Antwortet eine API mit einer reinen Liste auf oberster Ebene, macht n8n daraus ohnehin schon ein Item pro Eintrag. Steckt die Liste dagegen als Feld in der Antwort, etwa unter results, häng den Node Split Out dahinter und trag den Feldnamen unter Fields To Split Out ein. Danach läuft der nächste Node pro Eintrag (Kapitel 9).

Viele Seiten, viele Items: Pagination und Batching

Zwei weitere Einträge unter Add option lösen die häufigsten Probleme mit echten APIs.

Pagination holt Ergebnisseiten nach. Viele Dienste geben pro Aufruf nur 50 oder 100 Einträge zurück und verstecken den Rest hinter einer zweiten, dritten, vierten Seite. Füg die Option Pagination hinzu und stell den Pagination Mode ein; neben Off stehen dort zwei Wege zur Wahl.

Der erste heißt Update a Parameter in Each Request und zählt bei jedem Aufruf einen Parameter hoch. Darunter steht die Liste Parameters mit den Feldern Type (bleibt auf Query), Name und Value. Unter Name trägst du ein, wie der Seitenzähler heißt, oft page; unter Value kommt die Expression {{ $pageCount + 1 }}.

Der zweite, Response Contains Next URL, folgt der Adresse, die die Antwort selbst mitliefert. Die trägst du unter Next URL als Expression ein, in der Form {{ $response.body["next-page"] }}. Wie das Feld heißt, steht in der Doku deiner API; ein einheitliches Standardfeld gibt es dafür nicht. Wann Schluss ist, entscheidet Pagination Complete When, voreingestellt auf Response Is Empty.

Stell beim ersten Ausprobieren Limit Pages Fetched auf an und Max Pages auf 3. Sonst dreht der Node Runde um Runde, falls die Abbruchbedingung nicht greift. Das habe ich beim ersten Mal falsch gemacht und einer fremden API 4000 Requests geschickt.

Batching bremst dich absichtlich aus. Bekommt der Node 500 Items herein, feuert er ohne Batching 500 Requests hintereinander ab, und viele Dienste antworten darauf mit 429. Füg die Option Batching hinzu. Items per Batch steht dann auf 50, Batch Interval (ms) auf 1000. Übersetzt: 50 Anfragen, eine Sekunde Pause, die nächsten 50. Bei einer strengen API setzt du Items per Batch auf 1 und das Intervall hoch. Langsam, aber es kommt an. Kapitel 23 geht das im Zusammenhang durch.

Authentication: kurz angerissen

Verlangt ein Dienst einen Login, lass Authentication nicht auf None stehen. Kennt n8n den Dienst bereits, wähle Predefined Credential Type. Darunter erscheint das Feld Credential Type, dort suchst du den Dienst aus der Liste.

Kennt n8n ihn nicht, wähle Generic Credential Type. Darunter erscheint Generic Auth Type. Schickt die API ihren Schlüssel als Authorization: Bearer …, nimm Bearer Auth und trag den Schlüssel unter Bearer Token ein. Das Wort „Bearer“ setzt n8n selbst davor. Braucht die API einen eigenen Header wie X-API-Key, nimm Header Auth und füll Name und Value aus.

Niemals den Token offen in die URL schreiben. Wie Credentials sicher gespeichert werden, ist Thema von Kapitel 12.

Mini-Übung: einen POST senden und die Antwort lesen

Wir schicken Daten an einen offenen Echo-Dienst. Der spiegelt zurück, was er bekommt, und verlangt keinen Account. So siehst du genau, was bei ihm angekommen ist.

  1. Einen HTTP-Node anlegen

    Häng an einen manuellen Trigger einen HTTP Request und öffne ihn.

  2. Method auf POST stellen

    Feld Method → POST.

  3. Die URL eintragen

    Ins URL-Feld: https://postman-echo.com/post

  4. Body einschalten

    Send Body an, Body Content Type = JSON, Specify Body = Using JSON.

  5. Den Body eintippen

    Trag dieses JSON ein (gern mit Expression beim Zeitstempel):

  Body (JSON)
{
  "gruss": "Hallo aus n8n",
  "zeit": "{{ $now.toFormat('dd.MM.yyyy HH:mm') }}"
}

  1. Ausführen

    „▶ Schritt ausführen“ klicken. Rechts erscheint die Antwort.

  2. Die Spiegelung finden

    Such im Ergebnis das Feld data. Der Echo-Dienst gibt dort exakt deinen Body zurück. Damit ist bewiesen, dass dein POST samt JSON sauber angekommen ist. Daneben liegen noch args, files, form, headers, json und url. Die kannst du fürs Erste übergehen.

Wenn etwas schiefgeht

• Roter Fehler The value in the "JSON Body" field is not valid JSON? Im Body fehlt ein Komma, eine Klammer oder ein Anführungszeichen. Die Vorschau zeigt dir die Stelle. Unter n8n 1.x lautet dieselbe Meldung JSON parameter needs to be valid JSON.

• Code 405 (Method Not Allowed)? Du sendest GET an eine Adresse, die POST erwartet (oder umgekehrt). Method anpassen.

Selbsttest

  • Welche Method nimmst du zum Lesen, welche zum Senden?
  • Was ist der Vorteil der „Send Query Parameters“-Liste gegenüber Parametern direkt in der URL?
  • Wie machst du aus einer API-Liste „ein Item pro Eintrag“?
  • Was bedeutet ein Antwortcode 401, und woran liegt es meist?
  • Wofür ist „Import cURL“ gut?
  • Welche Option holst du dir, wenn eine API pro Aufruf nur 100 Einträge liefert?
Antworten 1) GET zum Lesen, POST zum Senden. · 2) Übersichtlich, und jeder Wert kann eine Expression sein; n8n baut die URL korrekt zusammen. · 3) Mit dem Node Split Out dahinter, Feld Fields To Split Out. Im HTTP-Request-Node selbst gibt es dafür keine Option mehr. · 4) Nicht angemeldet oder keine Berechtigung. Meist fehlt das Auth-Token oder es ist abgelaufen. · 5) Einen curl-Befehl aus einer API-Doku einfügen, n8n füllt den Node automatisch aus. · 6) Unter Add option den Eintrag Pagination.

Du kannst jetzt Daten holen und senden. Zwischen „rein“ und „raus“ liegt aber die eigentliche Arbeit: Daten umformen. Im nächsten Kapitel lernst du die Werkzeuge dafür kennen: Edit Fields (Set), Code und Filter. Bevor du weiterblätterst, schick den Echo-Request noch einmal mit einem absichtlich kaputten Body los, etwa ohne das Komma zwischen den beiden Zeilen. Die Fehlermeldung wirst du im Lauf dieses Buchs noch oft sehen; es hilft, sie einmal bewusst ausgelöst zu haben.
