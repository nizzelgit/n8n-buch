20 KI & Agenten

AI-Agent, Chat-Trigger, Memory & Tools

In diesem Kapitel baust du einen kleinen Chat-Agenten, der Fragen entgegennimmt, sich den Gesprächskontext merkt und bei Bedarf externe Werkzeuge nutzt. Der wichtige Unterschied zu Kapitel 17: Hier ist die KI nicht nur ein Klassifikator. Sie entscheidet, ob ein Tool gebraucht wird.

⏱ ca. 45 Minuten 🎯 Niveau: Fortgeschrittene Grundlagen 🧩 Voraussetzung: Kapitel 6–12, 17

📋 Was du brauchst

  • Eine n8n-Instanz mit den AI-/LangChain-Nodes.
  • Eine Chat-Model-Credential, z. B. OpenAI, Anthropic, Mistral, Groq oder Azure OpenAI.
  • Für das Beispiel keine weitere Credential: Die Wetterdaten kommen über die freie Open-Meteo-API.
  • Ein Testfenster im n8n-Chat. Veröffentliche den Chat erst nach den Tests.
Agent heißt nicht Autonomie ohne Grenzen Ein Agent darf nur die Werkzeuge bekommen, die er wirklich braucht. Lesende Tools sind zum Lernen gut. Schreibende Tools wie E-Mail senden, CRM ändern oder Dateien löschen gehören hinter eine Freigabe. Seit n8n 2.6.0 gibt es dafür einen eingebauten Human-review-Schritt. Wie du ihn setzt, steht in Schritt 12.

Das Ziel

Wir bauen einen Wetter-Chat. Der Nutzer schreibt eine Frage wie „Wie wird das Wetter morgen in Hamburg?“. Der Chat Trigger startet den Workflow, der AI Agent nutzt zwei HTTP-Tools, merkt sich den Ort über Memory und antwortet im Chat. Das Beispiel ist absichtlich klein: Es zeigt das Agenten-Muster, ohne einen riskanten Geschäftsprozess auszulösen.

⚡ Agenten-Muster Ein Agent besteht praktisch aus vier Dingen: Chat-Eingang, Modell, Memory und Tools. Ohne klare Tool-Grenzen wird aus Automatisierung schnell unkontrolliertes Raten.

Skeptische Faustregel Wenn der Ablauf deterministisch ist, nimm keinen Agenten. Wenn das Modell wirklich entscheiden muss, welches Werkzeug passt, ist ein Agent sinnvoll.

Zwei Wege zu einem Agenten

Seit 2026 gibt es neben dem AI-Agent-Node auch den Agent Builder. Dort ist ein Agent ein eigenes Objekt im Projekt, gleichrangig neben den Workflows. Er steckt also in keinem Workflow. Du wählst links dein Projekt, gehst auf den Tab Agents und klickst Create Agent. Danach konfigurierst du Model, Instructions, Tools, Skills, Knowledge und Memory. Über Preview testest du den Entwurf, mit Publish geht er live. Das Ganze ist noch jung: n8n bezeichnet die Agenten selbst als Preview-Funktion. Selbst gehostet laufen sie ab n8n 2.32.3, und dafür muss agents in N8N_ENABLED_MODULES stehen.

Aus einem Workflow heraus nutzt du solche Agenten auf zwei Arten. „Create agents inline“ setzt einen Agenten direkt als Node in den Workflow. „Message existing agents“ schickt eine Nachricht an einen bereits veröffentlichten Agenten und holt dessen Antwort zurück. Wir bleiben hier trotzdem beim AI-Agent-Node, denn dort siehst du jeden Baustein einzeln auf dem Canvas: Modell, Memory, Tools. Genau diese Sicht nimmt dir der Agent Builder ab.

Schritt 1: Workflow und Chat Trigger anlegen

Der Chat Trigger startet bei jeder Nachricht eine Workflow-Ausführung. Eine Unterhaltung mit zehn Nachrichten sind also zehn Ausführungen. Das ist für Kosten und Rate-Limits wichtig.

  1. Neuen Workflow erstellen

    Erstelle einen Workflow und nenne ihn Wetter-Chat-Agent.

  2. Chat Trigger hinzufügen

    Klicke auf Add first step…, suche chat trigger und wähle Chat Trigger.

  3. Öffentlichkeit kurz einschalten

    Setze Make Chat Publicly Available für einen Moment auf an. Solange der Schalter aus ist, blendet n8n die beiden nächsten Felder gar nicht erst ein.

  4. Hosted Chat wählen

    Wähle unter Mode den Eintrag Hosted Chat. n8n liefert die Chat-Seite dann selbst aus, und du brauchst für dieses Kapitel keinen eigenen Chat-Client.

  5. Starttext setzen

    Trage in Initial Message(s) z. B. Frag mich nach dem Wetter in einer Stadt. ein. Jede Zeile in diesem Feld wird eine eigene Startnachricht.

  6. Öffentlichkeit wieder ausschalten

    Setze Make Chat Publicly Available zurück auf aus. Getestet wird im n8n-internen Chat. Veröffentlichen kommt in Schritt 13, wenn die Tools laufen.

Wenn du sofort veröffentlichst Ohne Authentifizierung kann jeder mit der Chat-URL Ausführungen und Modellkosten verursachen. Für Tests reicht der interne Chat in n8n.

Schritt 2: AI Agent hinzufügen

Der Agent bekommt die Chatnachricht vom Trigger. Er arbeitet als Tools Agent und erwartet ein Chat Model sowie mindestens ein Tool. Stand Juli 2026 liefert n8n 2.32.x den AI Agent in der Node-Version 3.1 aus. Die frühere Auswahl verschiedener Agent-Typen gibt es seit n8n 1.82.0 nicht mehr, alle AI-Agent-Nodes laufen als Tools Agent. Für reine Textantworten wäre eine Basic LLM Chain schlichter.

  1. AI Agent anhängen

    Schließe die Detailansicht. Ziehe vom Chat Trigger eine Linie ins Leere, suche ai agent und wähle AI Agent.

  2. Prompt aus dem Chat übernehmen

    Setze Source for Prompt (User Message) auf Connected Chat Trigger Node. Das ist die Voreinstellung, meist musst du also nichts ändern. Der Agent liest dann das Feld chatInput aus dem direkt verbundenen Chat Trigger. In älteren Versionen hieß dieses Feld schlicht Prompt und die Option Take from previous node automatically. Die zweite Option heißt Define below; dann tippst du den Text selbst in das Feld Prompt (User Message).

  3. System Message öffnen

    Klicke unten im Node auf Add Option und wähle System Message. Dort kommt gleich die Arbeitsregel für den Agenten hinein.

  4. Max Iterations begrenzen

    Füge über Add Option auch Max Iterations hinzu und setze den Wert für den Anfang auf 4. Voreingestellt sind 10. Ein niedriges Limit verhindert lange Tool-Schleifen.

  System Message
Du bist ein vorsichtiger Wetter-Assistent in n8n.
Antworte auf Deutsch, kurz und überprüfbar.

Regeln:
- Nutze Tools nur, wenn du externe Wetter- oder Ortsdaten brauchst.
- Frage nach, wenn der Ort fehlt oder mehrdeutig ist.
- Erfinde keine Messwerte.
- Nenne Unsicherheit, wenn ein Tool keine Daten liefert.
- Speichere keine sensiblen personenbezogenen Daten im Gespräch.
- Führe keine Aktionen außerhalb der bereitgestellten Tools aus.
⚡ Begrenze Iterationen Ein Agent kann mehrmals denken, ein Tool aufrufen, Tool-Antwort lesen und erneut entscheiden. Das ist nützlich, aber nicht kostenlos. Setze beim Lernen ein niedriges Limit.
Streaming ist voreingestellt an In den Optionen des Agenten steht Enable Streaming standardmäßig auf an. Die Antwort läuft dann Stück für Stück in den Chat. Damit das greift, muss im Chat Trigger der Response Mode auf Streaming stehen. Du findest ihn dort unten unter Options, hinter der Schaltfläche Add Field. Voreingestellt ist When Last Node Finishes. Passt beides nicht zusammen, zeigt n8n nach der Ausführung einen Hinweis im Ausgabe-Bereich an.

Schritt 3: Chat Model verbinden

Der Agent selbst ist noch kein Modell. Er braucht ein Chat Model als Unter-Node.

  1. Model-Anschluss öffnen

    Klicke am AI-Agent-Node auf den Anschluss Chat Model.

  2. Chat Model wählen

    Wähle z. B. OpenAI Chat Model, Anthropic Chat Model oder ein anderes unterstütztes Modell.

  3. Credential auswählen

    Wähle deine Credential. Lege keine API-Keys im Prompt oder in Codefeldern ab.

  4. Temperatur niedrig halten

    Klicke im Chat Model auf Add Option, wähle Sampling Temperature und setze den Wert für dieses Beispiel auf 0.2. Voreingestellt sind 0.7. Faktenantworten sollen stabil sein, nicht poetisch.

Schritt 4: Simple Memory anschließen

Mit Memory fangen Folgefragen im selben Chat nicht bei null an. Ohne Memory versteht der Agent „morgen dort?“ nicht zuverlässig.

  1. Memory-Anschluss öffnen

    Klicke am AI-Agent-Node auf Memory und wähle Simple Memory.

  2. Session ID setzen

    Setze Session ID auf Connected Chat Trigger Node. Damit nutzt der Speicher die Session aus dem Chat Trigger.

  3. Fenster begrenzen

    Setze Context Window Length z. B. auf 8. Voreingestellt sind 5. Der Agent braucht nicht die komplette Lebensgeschichte des Chats.

  4. Chat Trigger mit Memory verbinden

    Wenn du im Chat Trigger später Load Previous Session auf From Memory setzt, verbinde denselben Simple-Memory-Node auch mit dem Chat Trigger. n8n empfiehlt das ausdrücklich, damit beide Nodes dieselbe Quelle lesen. Bei Connected Chat Trigger Node gilt eine Session nämlich nur innerhalb eines Memory-Nodes. Zwei getrennte Memory-Nodes teilen sich nur dann eine Session, wenn du in beiden auf Define below umstellst und denselben Key einträgst.

Simple Memory ist nicht immer produktionsfest Simple Memory legt den Verlauf lokal in der n8n-Instanz ab. Im Queue-Mode oder bei Multi-Main landen nicht alle Nachrichten beim selben Worker, deshalb funktioniert der Node dort in einem publizierten Workflow nicht. n8n blendet im Node selbst einen Hinweis dazu ein und verweist auf Redis, Postgres oder einen anderen persistenten Memory-Node.

Schritt 5: Das erste Tool für die Ortssuche

Der Agent soll nicht raten, welche Koordinaten Hamburg hat. Das erste Tool ruft die Geocoding-API von Open-Meteo auf und übersetzt einen Ortsnamen in Koordinaten.

  1. Tool-Anschluss öffnen

    Klicke am AI-Agent-Node auf Tool und wähle den normalen HTTP Request-Node als Tool. Den alten HTTP Request Tool-Node hat n8n ausgeblendet, er taucht in der Suche gar nicht mehr auf.

  2. Tool benennen

    Nenne das Tool Ort suchen.

  3. Beschreibung eintragen

    Schreibe als Beschreibung: Sucht zu einem Ortsnamen die wahrscheinlichsten Koordinaten.

  4. Methode setzen

    Setze Method auf GET.

  5. URL eintragen

    Setze die URL auf die folgende Expression.

  URL · Ort suchen
https://geocoding-api.open-meteo.com/v1/search?name={{ $fromAI('city', 'Stadt oder Ort aus der Nutzerfrage', 'string') }}&count=1&language=de&format=json
Was $fromAI() hier bedeutet $fromAI('city') ist kein Zugriff auf ein vorhandenes JSON-Feld. Es ist eine Aufforderung an das Modell: „Fülle diesen Tool-Parameter sinnvoll aus.“ Die Funktion kennt vier Argumente in dieser Reihenfolge: key, description, type, defaultValue. Pflicht ist nur key. Bei type sind string, number, boolean und json erlaubt, ohne Angabe gilt string. Wenn du lieber klickst als tippst: Jedes passende Feld eines Tools hat rechts einen Stern-Button, der genau so eine Expression für dich einsetzt.

Schritt 6: Das zweite Tool für die Wetterdaten

Das zweite Tool ruft die Wetterdaten mit Koordinaten ab. Der Agent soll erst den Ort suchen und dann mit den Koordinaten das Wetter holen.

  1. Zweites HTTP-Request-Tool hinzufügen

    Füge am Tool-Anschluss des AI Agent einen weiteren normalen HTTP Request-Node als Tool hinzu.

  2. Tool benennen

    Nenne es Wetter holen.

  3. Beschreibung eintragen

    Schreibe: Holt aktuelle Wetterdaten und Tageswerte für gegebene Koordinaten.

  4. Methode setzen

    Setze Method wieder auf GET.

  5. URL eintragen

    Setze die URL auf diese Expression. Die Beschreibungen helfen dem Modell, Latitude und Longitude aus dem Ergebnis von Ort suchen zu übernehmen.

  URL · Wetter holen
https://api.open-meteo.com/v1/forecast?latitude={{ $fromAI('latitude', 'Breitengrad aus dem Tool Ort suchen', 'number') }}&longitude={{ $fromAI('longitude', 'Längengrad aus dem Tool Ort suchen', 'number') }}&current=temperature_2m,precipitation,wind_speed_10m&daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max&timezone=auto
Wenn der Agent das zweite Tool falsch füllt Dann ist die Tool-Beschreibung zu vage oder der erste Tool-Output zu groß. Mache die Beschreibung enger und bitte den Agenten im System Prompt ausdrücklich: „Nutze zuerst Ort suchen und verwende dessen latitude/longitude.“

Schritt 7: Agentenregel für die Tool-Reihenfolge schärfen

Jetzt ergänzen wir die System Message. Das ist keine Garantie, aber eine wichtige Leitplanke.

  1. AI Agent öffnen

    Doppelklicke den AI-Agent-Node.

  2. System Message ergänzen

    Erweitere die System Message um die folgenden Regeln.

  Zusatzregeln für Tools
Tool-Nutzung:
- Wenn der Nutzer einen Ort nennt, rufe zuerst "Ort suchen" auf.
- Verwende aus dem ersten Ergebnis latitude und longitude.
- Rufe danach "Wetter holen" auf.
- Wenn kein Ort genannt wird, frage nach dem Ort.
- Wenn der Nutzer "dort" oder "dieselbe Stadt" sagt, nutze den Ort aus Memory.
- Antworte mit Ort, Zeitraum, Temperatur, Regenwahrscheinlichkeit und kurzer Handlungsempfehlung.

Schritt 8: Ersten Chat-Test ausführen

Prüfe jetzt die Werkzeugkette. Die Antwort allein sagt zu wenig.

  1. Chat öffnen

    Klicke auf dem Canvas auf Open chat. Damit öffnest du den internen Testchat, ohne den Workflow zu veröffentlichen.

  2. Konkrete Frage stellen

    Schreibe: Wie wird das Wetter morgen in Hamburg?

  3. Antwort prüfen

    Die Antwort sollte Hamburg nennen und konkrete Wetterdaten enthalten. Sie darf keine exakten Werte erfinden, wenn die API nichts geliefert hat.

  4. Execution öffnen

    Öffne die Ausführung. Prüfe, ob Ort suchen und Wetter holen aufgerufen wurden.

⚡ Execution lesen, nicht nur Chat lesen Eine plausible Chatantwort beweist wenig. Öffne die Ausführung und prüfe Tool-Aufrufe, Parameter und Rückgaben.

Schritt 9: Memory mit Folgefragen testen

Memory ist erst dann sichtbar, wenn du absichtlich eine Folgefrage stellst.

  1. Erste Nachricht senden

    Schreibe: Merke dir bitte: Mein Arbeitsort ist Leipzig.

  2. Folgefrage senden

    Schreibe danach: Wie wird das Wetter morgen dort?

  3. Ort prüfen

    Die Antwort muss Leipzig verwenden. Wenn der Agent wieder nach dem Ort fragt, ist Memory nicht korrekt verbunden oder die Session ID stimmt nicht.

  4. Neuen Chat starten

    Starte eine neue Unterhaltung. Frage wieder Wie wird das Wetter morgen dort?. Jetzt sollte der Agent nachfragen, weil der alte Kontext nicht in diese neue Session gehört.

Memory ist kein Wissensspeicher Memory ist Gesprächsverlauf, keine Datenbank. Für dauerhaftes Wissen über Dokumente, Produkte oder interne Regeln brauchst du später RAG oder eine normale Datenquelle.

Schritt 10: Antwort manuell formen, falls nötig

Im einfachen Fall sendet der Chat Trigger die Agent-Ausgabe direkt zurück. Anders wird es, sobald nach dem Agenten noch Nodes laufen. Dann hast du zwei Möglichkeiten. Entweder liefert der letzte Node ein Feld output oder text. Oder du stellst im Chat Trigger unter Options den Response Mode auf Using Response Nodes und schickst die Antwort über einen Chat-Node. Diese Option siehst du beim Hosted Chat. Im Modus Embedded Chat heißt das Gegenstück Using 'Respond to Webhook' Node.

  1. Direktantwort beibehalten

    Für dieses Kapitel lässt du den Agenten die finale Antwort liefern. Das ist die einfachste Form.

  2. Optional Code-Node anhängen

    Wenn du die Antwort formatieren willst, hänge einen Code-Node nach dem Agenten.

  3. Feldnamen beachten

    Für eine manuell gebaute Antwort kennt der Chat Trigger genau zwei Feldnamen: output und text. Heißt das Feld anders, schickt er das komplette Objekt in den Chat statt nur den Wert.

  Optional · Antwort normalisieren
return {
  json: {
    output: $json.output ?? $json.text ?? 'Ich konnte keine Antwort erzeugen.'
  }
};

Schritt 11: Fehlerfälle sichtbar machen

Agentenfehler sind oft leise: falscher Ort, falscher Tool-Parameter, leere API-Antwort. Baue deshalb kleine Kontrollfragen ein.

FehlerWoran du ihn erkennstGegenmaßnahme
Tool nicht genutztExecution zeigt keinen Tool CallSystem Message enger formulieren, Tool-Beschreibung verbessern
falsche StadtGeocoding liefert anderen OrtAgent soll bei Mehrdeutigkeit nach Land/Bundesland fragen
zu viele Tool CallsAgent ruft dieselbe API mehrfach aufMax Iterations senken, Prompt präzisieren
kein MemoryFolgefrage „dort“ scheitertSession ID prüfen, denselben Memory-Node verbinden

Konkrete Testfälle Teste immer: konkrete Frage, mehrdeutige Frage, Folgefrage mit Memory, API-Fehler. Scheitert einer dieser Fälle, gehört der Agent noch nicht vor echte Nutzer.

Schritt 12: Freigabe vor riskanten Tool-Aufrufen

Unser Wetter-Agent liest nur. Sobald ein Tool etwas verändert, gehört ein Mensch dazwischen. Seit n8n 2.6.0 baust du diese Freigabe nicht mehr aus Wait- und IF-Nodes zusammen. Sie hängt direkt an der Verbindung zwischen Agent und Tool, und der Agent kommt an dem Tool ohne Zustimmung nicht vorbei.

  1. Verbindung zum Tool aufklappen

    Fahre auf dem Canvas über die Verbindung vom AI Agent zu dem Tool, das du absichern willst, und klicke auf das +-Symbol. Der Tooltip dazu lautet Add human review step. Der zweite Weg führt über den Anschluss Tool am Agenten, dort findest du dieselbe Rubrik.

  2. Kanal auswählen

    n8n öffnet das Tools-Panel mit der Rubrik Human review. Zur Auswahl stehen Chat, Slack, Discord, Telegram, Microsoft Teams, Gmail, WhatsApp Business Cloud, Google Chat und Microsoft Outlook. Die Freigabe darf über einen anderen Kanal laufen als das Gespräch selbst: Nutzer im Chat, Freigabe in Slack.

  3. Tools hinter den Review-Schritt hängen

    Verbinde die Tools, die eine Freigabe brauchen, mit dem Tool-Anschluss des Review-Schritts. Alle übrigen Tools bleiben direkt am Agenten und laufen weiterhin ohne Rückfrage.

  4. Nachricht für die freigebende Person schreiben

    Im Review-Node stehen dir $tool.name und $tool.parameters zur Verfügung. Nimm beide in die Nachricht auf, sonst muss jemand blind zustimmen.

  5. Ablehnung im System Prompt behandeln

    Ergänze die System Message um den Hinweis, welche Tools eine Freigabe brauchen und was bei einer Ablehnung passieren soll. Ohne diesen Hinweis reagiert der Agent auf ein Nein oft ratlos.

  Nachricht im Review-Schritt
The AI wants to use {{ $tool.name }} with the following parameters:
{{ JSON.stringify($tool.parameters, null, 2) }}
Rückfragen mitten im Gespräch Neben der Tool-Freigabe gibt es den Chat-Node mit den Operationen Send Message und Send and Wait for Response. Damit hält der Workflow an und wartet auf eine Antwort im Chat, entweder als freier Text oder über Approve-Buttons. Dafür muss im Chat Trigger der Response Mode auf Using Response Nodes stehen. Im Modus Embedded Chat läuft der Chat-Node nicht. Hängst du ihn als Tool an den Agenten, kann der Agent von sich aus nachfragen, statt zu raten.

Schritt 13: Chat sicher veröffentlichen

Erst wenn die Tests passen, machst du den Chat öffentlich. Öffentlich heißt: Jemand außerhalb des Editors kann Ausführungen starten.

  1. Chat Trigger öffnen

    Doppelklicke den Chat Trigger.

  2. Public einschalten

    Setze Make Chat Publicly Available auf an.

  3. Authentifizierung wählen

    Wähle für Tests Basic Auth oder n8n User Auth. None ist nur für absichtlich öffentliche Demos sinnvoll.

  4. CORS begrenzen

    Die Einstellung heißt Allowed Origins (CORS) und liegt unter Options. Voreingestellt ist *, also alle Herkünfte. Trage deine konkrete Domain ein, sobald du den Chat in eine Website einbettest. Mehrere Domains gehen als kommagetrennte Liste.

  5. Load Previous Session prüfen

    Wenn Nutzer frühere Chatnachrichten laden sollen, setze Load Previous Session auf From Memory und nutze denselben Memory-Node wie am Agenten. Erst mit dieser Einstellung erscheint am Chat Trigger überhaupt der Memory-Anschluss.

  6. Workflow publishen

    Warte auf Auto-Save und klicke erst dann Publish.

Chat Hub statt eigener Chat-Seite Im Chat Trigger gibt es zusätzlich den Schalter Make Available in n8n Chat Hub. Damit taucht dein Agent im Chat-Bereich von n8n auf, unter dem Namen und der Beschreibung, die du in Agent Name und Agent Description einträgst. Für interne Helferlein ist das der kürzeste Weg zu Kolleg:innen.
Schreibende Tools brauchen Review Wenn du später ein Gmail-, Slack-, CRM- oder Datenbank-Tool anschließt, hänge es hinter einen Human-review-Schritt aus Schritt 12. Der Mensch sieht dann vor der Ausführung, welches Tool mit welchen Parametern laufen soll, und entscheidet mit Approve oder Deny.

Antworten 1) Wenn das Modell entscheiden muss, welches Tool nötig ist. · 2) Weil Wetter-APIs Koordinaten brauchen und der Ort erst aufgelöst werden muss. · 3) Weil das Modell den Parameter aus Kontext und Tool-Beschreibung ableitet. · 4) Mit einer Folgefrage wie „morgen dort?“ in derselben Session und einer neuen Session als Gegenprobe. · 5) Alle Tools mit Außenwirkung: senden, löschen, kaufen, CRM ändern, Daten veröffentlichen. · 6) Am + auf der Verbindung zwischen AI Agent und Tool, über Add human review step.

Das Grundmuster steht: Chat rein, Modell entscheidet, Tools liefern Daten, Memory hält den Gesprächskontext. Bevor du weitergehst, nimm dir eine Übung vor. Hänge ein drittes Tool an, das absichtlich falsch beschrieben ist, etwa Holt Daten., und schau in der Execution zu, wie der Agent daneben greift. Diese eine Minute erklärt mehr über Tool-Beschreibungen als jeder Merksatz. Im nächsten KI-Kapitel wird aus Gesprächsgedächtnis ein Wissenssystem: RAG über eigene Dokumente.
