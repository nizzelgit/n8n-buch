Credentials & Authentifizierung

Die meisten interessanten Dienste — Gmail, Telegram, Sheets, OpenAI — verlangen einen Login. In n8n gibst du Zugangsdaten aber nicht mitten in den Workflow ein, sondern legst sie als sicher verschlüsselte Credential an. Dieses Kapitel zeigt, wie das geht — und warum es so viel sicherer ist.

⏱ ca. 15 Minuten 🎯 Niveau: Einstieg → Mittel 🧩 Voraussetzung: Kapitel 8 (HTTP)

📋 Was du mitbringen solltest

  • Du hast den HTTP-Node gesehen (Kapitel 8) und das Feld „Authentication" bemerkt.
  • Niemals echte Tokens in dieses Buch oder in geteilte Dateien schreiben — hier nur Platzhalter.

Was eine Credential ist — und warum getrennt

Eine Credential ist ein sicher gespeichertes Geheimnis: ein API-Schlüssel, ein Token oder ein OAuth-Login. n8n speichert die Werte verschlüsselt und getrennt vom Workflow. Im Node wählst du nur den Namen der Credential — die Geheimwerte tauchen im Workflow selbst nirgends auf.

Warum getrennt?Konkret
SicherheitBeim Export/Teilen eines Workflows gehen die Geheimnisse nicht mit.
WiederverwendungEine Credential nutzt du in beliebig vielen Nodes und Workflows.
PflegeToken abgelaufen? Einmal zentral ändern — alle Nodes nutzen sofort den neuen.
⚡ Die eine Regel Geheimnisse gehören in Credentials — nie direkt in ein Feld, eine URL oder eine Expression. Das ist die wichtigste Sicherheits-Gewohnheit in n8n.

Zwei Wege, sich zu authentifizieren

  • Vordefinierter Credential-Typ: Kennt n8n den Dienst (Telegram, Google, OpenAI, Slack …), gibt es einen fertigen Typ. Du füllst nur die passenden Felder — n8n weiß, wie der Login funktioniert.
  • Generisch (im HTTP-Node): Für jede beliebige API ohne eigenen Node. Wähle im HTTP-Node Generic Credential Type → meist Header Auth (z. B. Header Authorization = Bearer DEIN_TOKEN) oder Basic / Query / OAuth2.

Eine Credential anlegen (Schritt für Schritt)

Am einfachsten legst du sie direkt aus dem Node an, der sie braucht.

  1. Im Node das Credential-Feld öffnen

    Im Node steht oben „Credential to connect with". Klick auf das Aufklappmenü → „+ Create new credential".

  2. Die Felder ausfüllen

    Es öffnet sich ein Formular mit genau den Feldern, die der Dienst braucht — z. B. bei Telegram nur das Access Token vom BotFather.

  3. Speichern (und ggf. testen)

    Auf „Save" klicken. Viele Credentials prüfen die Verbindung sofort und zeigen ein grünes „Connection successful".

  4. Benennen

    Gib der Credential oben einen sprechenden Namen, z. B. Telegram – Wetter-Bot. So findest du sie später in anderen Nodes wieder.

OAuth: Login per Klick

Manche Dienste (Google, Microsoft …) nutzen OAuth statt eines simplen Tokens. Dann erscheint im Credential-Formular ein Knopf „Sign in with …" / „Connect". Ein Klick öffnet das Login-Fenster des Anbieters, du bestätigst den Zugriff — und n8n speichert den Zugang automatisch. Kein Kopieren von Schlüsseln nötig.

Eine Credential, viele Nodes Einmal angelegt, taucht deine Credential in jedem passenden Node im Aufklappmenü auf. Du wählst sie einfach aus — neu anlegen musst du sie nie wieder. Zentral verwalten kannst du alle unter dem Menüpunkt „Credentials".

Sicherheits-Gewohnheiten

  • Geheimnisse nur in Credentials — nie in URL, Feld oder Expression.
  • Sparsam mit Rechten: Gib einem Token nur die Berechtigungen, die der Workflow wirklich braucht.
  • Regelmäßig erneuern (Rotation) und alte/ungenutzte Tokens widerrufen.
  • Self-hosted: Für Werte, die sich je Umgebung unterscheiden, eignen sich Umgebungsvariablen — mehr in Kapitel 24.
Wenn etwas schiefgeht

• Fehler 401/403? Token fehlt, ist falsch kopiert (Leerzeichen!) oder abgelaufen. Credential öffnen, Wert neu einsetzen, speichern.

• OAuth-Verbindung „expired"? Einfach erneut „Connect"/„Reconnect" klicken und den Login wiederholen.

Mini-Übung: eine API mit Header-Token ansprechen

Wir richten im HTTP-Node eine generische Header-Authentifizierung ein (mit Platzhalter-Token).

  1. HTTP-Node, Authentication wählen

    Im HTTP-Node Authentication → Generic Credential Type → Header Auth.

  2. Credential anlegen

    „+ Create new credential". Feld Name = Authorization, Feld Value = Bearer DEIN_TOKEN (echtes Token natürlich privat halten).

  3. Speichern & benennen

    Save, Credential z. B. Beispiel-API – Header nennen.

  4. Verwenden

    Zurück im Node ist die Credential ausgewählt. Jeder Request schickt den Header nun automatisch mit — du musst ihn nie wieder eintippen, und er steht nicht im Workflow.

✅ Selbsttest

  • Warum trägt man Tokens nicht direkt in ein Node-Feld ein?
  • Was passiert mit Credentials, wenn du einen Workflow exportierst?
  • Wann nimmst du „Generic Credential Type → Header Auth"?
  • Ein abgelaufenes Token äußert sich meist als welcher Fehlercode?
  • Musst du dieselbe Credential für jeden Node neu anlegen?
Antworten 1) Sicherheit — Geheimnisse gehören verschlüsselt in Credentials, nicht in den Workflow. · 2) Sie gehen nicht mit; nur der Verweis bleibt. · 3) Für beliebige APIs ohne eigenen Node, die einen Token im Header erwarten. · 4) 401 (bzw. 403). · 5) Nein — einmal anlegen, überall aus dem Menü auswählen.
