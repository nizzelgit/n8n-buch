News-Aggregator mit Filter

Dieses Projekt sammelt regelmäßig neue RSS-Einträge, filtert sie nach deinen Interessen und schickt nur die relevanten Treffer weiter. Damit baust du keinen „noch einen Feedreader“, sondern einen kleinen Aufmerksamkeitsfilter: weniger Rauschen, bessere Signale.

⏱ ca. 40 Minuten 🎯 Niveau: Mittel 🧩 Voraussetzung: Kapitel 7–12

📋 Was du brauchst

  • n8n läuft und kann externe RSS-Feeds abrufen.
  • Eine Slack-Credential oder alternativ einen Telegram-Node aus Kapitel 13. Wir zeigen Slack; Telegram funktioniert analog.
  • Keinen API-Schlüssel: Wir verwenden den öffentlichen RSS-Feed https://hnrss.org/frontpage.
  • Ein Testkanal, damit du beim Entwickeln keine produktiven Kanäle flutest.
Kein perfekter Nachrichtenfilter Keyword-Filter sind grob. Sie finden „AI“ im Titel, aber verstehen den Inhalt nicht tief. Das ist Absicht: Wir bauen zuerst eine robuste, transparente Version. KI-Zusammenfassung und semantische Filter kommen später.

Das Ziel

Der Workflow läuft morgens automatisch, liest den Hacker-News-Frontpage-RSS-Feed, behält nur Einträge zu Automatisierung, KI oder n8n-ähnlichen Themen, begrenzt die Menge und sendet eine kompakte Slack-Zusammenfassung.

⚡ Der Kern dieses Projekts RSS-Feeds liefern viele Items. Der Filter reduziert die Liste, der Digest-Node macht aus mehreren Items wieder ein Item. Dieses „viele → wenige → eins“-Muster brauchst du für Reports, Monitoring und Recherche.

Schritt 1 — Workflow anlegen

  1. Neuen Workflow erstellen

    Gehe zur Workflow-Übersicht und klicke auf Create Workflow.

  2. Name setzen

    Klicke oben links auf den Workflow-Namen und schreibe: News-Aggregator.

  3. Auto-Save prüfen

    Warte, bis der Draft gespeichert ist.

Schritt 2 — Schedule-Trigger setzen

  1. Schedule Trigger hinzufügen

    Klicke auf das große +, suche schedule und wähle Schedule Trigger.

  2. Node öffnen

    Doppelklicke den Trigger.

  3. Täglichen Lauf einstellen

    Setze Trigger Interval auf Days, Days Between Triggers auf 1, Trigger at Hour auf 9am und Trigger at Minute auf 0.

  4. Einmal testen

    Klicke ▶ Schritt ausführen. Der Trigger erzeugt ein Test-Item.

Zeitzone prüfen Wie bei Projekt 1 gilt: 9 Uhr ist nur dann deine lokale 9 Uhr, wenn die n8n-Zeitzone stimmt. Prüfe das spätestens vor dem Publish.

Schritt 3 — RSS-Feed lesen

n8n hat einen RSS-Node. Je nach Version heißt er RSS Read, RSS Feed Read oder ähnlich. Er nimmt eine Feed-URL und gibt pro Feed-Eintrag ein Item aus.

  1. RSS-Node anhängen

    Schließe die Detailansicht. Ziehe vom Schedule-Trigger eine Linie ins Leere, suche rss und wähle den RSS-Read-Node.

  2. Node benennen

    Nenne ihn RSS lesen.

  3. Feed-URL eintragen

    Trage als URL ein: https://hnrss.org/frontpage

  4. Schritt ausführen

    Klicke ▶ Schritt ausführen. Rechts sollten mehrere Items erscheinen, typischerweise mit Feldern wie title, link, pubDate und content.

  5. Schema ansehen

    Wechsle rechts auf Schema. Merke dir besonders title und link.

Wenn keine Items erscheinen Prüfe zuerst die URL und deine Internetverbindung. RSS-Feeds können außerdem kurzzeitig langsam sein. Teste im Zweifel die URL direkt im Browser: Wenn dort XML erscheint, ist der Feed erreichbar.

Schritt 4 — Relevante Einträge filtern

Jetzt bauen wir den ersten groben Interessenfilter. Er lässt Einträge durch, deren Titel eines unserer Keywords enthält.

  1. Filter-Node anhängen

    Ziehe vom RSS-Node eine Linie ins Leere, suche filter und wähle Filter.

  2. Node benennen

    Nenne ihn Interessante Titel.

  3. Bedingung auf Expression stellen

    Im Bedingungsbereich setzt du links eine Expression. Wir wandeln den Titel in Kleinbuchstaben um, damit AI, ai und Ai gleich behandelt werden.

  4. Expression eintragen

    Trage links ein:

  Linke Seite der Filter-Bedingung
{{ ($json.title ?? "").toLowerCase() }}

  1. Operator wählen

    Wähle als Operator contains bzw. enthält.

  2. Keyword eintragen

    Trage rechts ai ein.

  3. Weitere OR-Bedingungen hinzufügen

    Füge mit OR zwei weitere Bedingungen hinzu: enthält automation und enthält workflow.

  4. Schritt ausführen

    Klicke ▶ Schritt ausführen. Im Ausgang sollten weniger Items stehen als im Eingang.

⚡ Erst grob filtern, dann verfeinern Ein grober Keyword-Filter ist besser als ein komplexer Filter, den du nicht mehr verstehst. Starte mit drei Keywords, beobachte eine Woche die Treffer und passe dann an.

Schritt 5 — Menge begrenzen

Ein Slack-Digest mit 30 Links ist kein Digest mehr. Wir begrenzen deshalb auf maximal fünf Treffer.

  1. Limit-Node anhängen

    Ziehe vom Filter-Node eine Linie ins Leere, suche limit und wähle Limit.

  2. Node benennen

    Nenne ihn Maximal 5 Treffer.

  3. Limit setzen

    Setze die Anzahl auf 5.

  4. Ausführen

    Klicke ▶ Schritt ausführen. Im Ausgang stehen höchstens fünf Items.

Warum Limit nach Filter? Wenn du erst begrenzt und dann filterst, könnten die ersten fünf Feed-Einträge zufällig irrelevant sein — dann bleibt nichts übrig. Erst filtern, dann begrenzen.

Schritt 6 — Digest bauen

Jetzt wird es interessant: Der Slack-Node soll nicht fünf einzelne Nachrichten senden, sondern eine kompakte Nachricht mit bis zu fünf Links. Dafür machen wir aus mehreren Items ein einziges Item.

  1. Code-Node anhängen

    Ziehe vom Limit-Node eine Linie ins Leere, suche code und wähle Code.

  2. Node benennen

    Nenne ihn Digest bauen.

  3. Modus wählen

    Setze den Modus auf Run Once for All Items. Wir brauchen alle Treffer gleichzeitig.

  4. Code einfügen

    Füge diesen Code ein:

  Code · Run Once for All Items
const items = $input.all();

const lines = items.map((item, index) => {
  const title = item.json.title ?? 'Ohne Titel';
  const link = item.json.link ?? item.json.guid ?? '';
  return `${index + 1}. ${title}\n${link}`;
});

return [{
  json: {
    count: items.length,
    text: items.length
      ? `News-Digest: ${items.length} Treffer\n\n${lines.join('\n\n')}`
      : 'News-Digest: Heute keine Treffer.'
  }
}];

  1. Schritt ausführen

    Klicke ▶ Schritt ausführen. Im Ausgang sollte genau 1 Item stehen.

  2. Text prüfen

    Öffne das Feld text. Es sollte mehrere nummerierte Links oder die Meldung „Heute keine Treffer“ enthalten.

Wenn der Code-Node Fehler meldet Prüfe zuerst den Modus. Dieser Code erwartet Run Once for All Items. Im Modus „Each Item“ gibt es $input.all() nicht in der gleichen Form.

Schritt 7 — Slack-Digest senden

  1. Slack-Node anhängen

    Ziehe vom Code-Node eine Linie ins Leere, suche slack und wähle Slack.

  2. Aktion wählen

    Wähle Send a message.

  3. Credential und Kanal wählen

    Wähle deine Slack-Credential und einen Testkanal, z. B. #news-test.

  4. Text auf Expression stellen

    Schalte das Textfeld auf Expression.

  5. Digest-Text einsetzen

    Trage ein: {{ $json.text }}

  6. Schritt ausführen

    Klicke ▶ Schritt ausführen. Im Slack-Testkanal sollte genau eine Digest-Nachricht erscheinen.

Wenn Slack mehrere Nachrichten sendet Dann hängt Slack wahrscheinlich vor dem Digest-Node oder der Digest-Node gibt mehrere Items zurück. Der Slack-Node muss hinter Digest bauen stehen, und dessen Ausgang muss 1 Item zeigen.

Schritt 8 — Gesamttest und Publish

  1. Zurück zum Canvas

    Drücke Esc, bis du alle Nodes siehst.

  2. Auto-Save prüfen

    Warte, bis der Draft gespeichert ist.

  3. Test workflow starten

    Klicke Test workflow. Prüfe, dass die Kette von links nach rechts grün durchläuft.

  4. Slack prüfen

    Kontrolliere den Testkanal. Es sollte eine einzige Nachricht mit höchstens fünf Links stehen.

  5. Publish klicken

    Wenn der Test passt, klicke oben rechts auf Publish.

  6. Ersten echten Lauf prüfen

    Nach dem ersten geplanten Lauf öffnest du Executions und prüfst, ob der automatische Lauf sauber war.

⚡ Beobachte Trefferqualität, nicht nur Technik Der Workflow kann technisch grün sein und trotzdem schlechte Treffer liefern. Sammle ein paar Tage Beispiele: Welche Keywords sind zu breit, welche fehlen? Danach schärfst du den Filter.

✅ Selbsttest

  • Warum gibt der RSS-Node mehrere Items aus?
  • Warum kommt der Limit-Node nach dem Filter?
  • Warum braucht der Digest-Code den Modus „Run Once for All Items“?
  • Woran erkennst du, dass Slack nur eine Nachricht senden wird?
  • Was ist bei einem News-Workflow wichtiger: grüne Häkchen oder Trefferqualität?
Antworten 1) Ein Feed-Eintrag wird zu einem Item. · 2) Sonst begrenzt du womöglich irrelevante Einträge, bevor du relevante findest. · 3) Er muss alle Treffer gleichzeitig zu einem Text zusammenfassen. · 4) Der Ausgang von Digest bauen zeigt 1 Item. · 5) Beides, aber nach der technischen Prüfung entscheidet die Trefferqualität über den Nutzen.
