0.1 Orientierung

Das 80/20 von n8n — die wichtigen 35 %

n8n listet inzwischen fast 2000 Integrationen, also fertige Anbindungen an andere Programme. Das klingt nach viel Lernstoff. Ist es aber nicht: Ein kleiner Kern erklärt fast alles, was du je bauen wirst. Dieses Kapitel ist die Landkarte dazu. Der Rest des Buchs füllt sie aus.

ca. 12 Minuten Niveau: Einstieg Grundlage für alle weiteren Kapitel

Bevor wir irgendetwas installieren oder klicken, bauen wir eine Landkarte im Kopf. Du musst hier noch nichts ausprobieren, nur lesen. Wenn du die folgenden sieben Bausteine verstehst, kannst du dir später fast jeden Workflow selbst herleiten, auch solche, die in diesem Buch gar nicht vorkommen. Alles andere sind Varianten und Spezialfälle.

Die Kernidee in einem Satz Ein n8n-Workflow ist eine Kette von Bausteinen (Nodes), durch die Daten (Items) von links nach rechts fließen. Jeder Node bekommt Daten herein, tut eine Sache und gibt Daten weiter. Ein „Workflow“ ist dabei einfach ein Ablauf, den n8n für dich automatisch ausführt.

Die 7 Bausteine, die fast alles erklären

1. Der Auslöser (Trigger): „Wann soll es losgehen?“

Jeder Workflow braucht mindestens einen Auslöser (englisch: Trigger). Am Anfang ist es genau einer. Er beantwortet die Frage, wann der Workflow startet. In der Praxis brauchst du fast immer nur drei:

  • Manual Trigger – der Start per Hand. Im Node-Panel (der Auswahlliste, aus der du neue Nodes hinzufügst) heißt der Eintrag „Trigger manually“. Gestartet wird dann mit dem Knopf Execute workflow; in älteren Versionen hieß er „Test workflow“. Diesen Trigger nutzt du zum Bauen und Ausprobieren.
  • Zeitplan (Schedule Trigger) – „jeden Tag um 8 Uhr“. Für Reports, Backups, Erinnerungen.
  • Webhook – „immer wenn jemand dieses Formular abschickt“ oder „immer wenn dieses andere System mir Daten schickt“. Das Tor zu praktisch jeder anderen Software.

Eine Sache, über die ich beim Umstieg auf n8n 2.0 selbst gestolpert bin: Schedule und Webhook laufen erst von allein, wenn du den Workflow veröffentlichst. n8n speichert deine Änderungen zwar automatisch, aber nur als Draft (Entwurf). Ein Entwurf läuft nie von allein. Erst wenn du auf Publish (veröffentlichen) klickst, geht genau dieser Stand live. Vorher startest du jede Ausführung selbst per Knopf. Falls du irgendwo vom Schalter „Active“ liest: Den gab es in n8n 1.x, heute nicht mehr.

MerkeSchedule + Webhook decken geschätzt 80 % aller realen Startpunkte ab.

2. Daten holen: der HTTP-Request-Node

n8n hat fertige Nodes für Google Sheets, Slack, Telegram, Notion und hunderte mehr. Der wichtigste einzelne Node ist trotzdem HTTP Request. Eine API ist eine Internet-Schnittstelle: eine Adresse, unter der ein Programm Daten für andere Programme bereitstellt. Mit dem HTTP-Request-Node sprichst du jede solche Schnittstelle an, auch die, für die es keinen fertigen Node gibt. Wer diesen Node beherrscht, ist von keiner Integration abhängig.

3. Daten umformen: Edit Fields (Set) und der Code-Node

Zwischen „Daten rein“ und „Daten raus“ liegt fast immer ein bisschen Umbau: Felder umbenennen, zusammenfügen, ausrechnen, filtern. Dafür reichen meist zwei Werkzeuge. Der Edit Fields (Set)-Node deckt die einfachen Fälle ab; auf dem Canvas (der Arbeitsfläche, auf der du Workflows baust) heißt er kurz „Edit Fields“. Der Code-Node übernimmt alles, was Logik braucht. Keine Sorge: Für die meisten Workflows brauchst du ihn gar nicht.

4. Entscheiden: If und Switch

„Wenn der Betrag über 1000 € liegt, schicke es an den Chef, sonst direkt verbuchen.“ Solche Verzweigungen baust du mit dem If-Node (zwei Wege) oder dem Switch-Node (viele Wege). Kleine Stolperfalle beim Suchen: In älteren n8n-Versionen hieß der Node „IF“ in Großbuchstaben, heute steht auf dem Node „If“.

5. Etwas auslösen: Aktions-Nodes

Am Ende soll etwas passieren: eine E-Mail raus, eine Zeile in Google Sheets, eine Slack-Nachricht, ein Eintrag im CRM. Das sind Aktions-Nodes. Sie funktionieren alle nach demselben Muster, das du einmal lernst.

6. Der rote Faden: Items und Expressions

Daten reisen als Items durch den Workflow. Ein Item ist ein kleines Datenpaket, zum Beispiel „eine E-Mail“ oder „eine Tabellenzeile“, notiert im JSON-Format (einer einfachen Textschreibweise für Daten). Um in einem späteren Node auf einen Wert aus einem früheren zuzugreifen, nutzt du Expressions: kleine Platzhalter wie {{ $json.email }}. Beim Ausführen setzt n8n dort den echten Wert ein. Das ist der wichtigste „Trick“, um Nodes miteinander zu verdrahten.

7. Verlässlichkeit: Fehlerbehandlung

Sobald ein Workflow echte Arbeit macht, geht auch mal etwas schief: Ein Dienst ist gerade nicht erreichbar, oder Daten sehen anders aus als erwartet. Das ist normal und kein Grund zur Panik. Lern trotzdem früh, solche Fehler abzufangen: Genau da liegt der Unterschied zwischen einem Bastel-Workflow und einem, dem man vertraut.
